# cloud/tariff —— 河北四网资费查询页 + 移动「资费专区」每日巡检

页面是**四网（移动 / 联通 / 电信 / 广电）一体化**的：顶部四个网别入口，点一下就切。
当前四网**全部接入**：

- **移动** —— 中国移动 APP「资费专区」河北全省（`province=311`）报备公示的全量资费目录，
  每天抓一次、比对上下线变更，约 **3887 条** / 18 个分类组合 / 每条 40 余字段；
- **联通** —— 中国联通 APP「资费专区」河北（`mxx.client.10010.com` / `queryTariffNew`），
  同样每日抓取比对，约 **4807 条在售 + 3092 条已下架 = 7899 条**（下架那批进「已下架」页签）；
- **广电** —— 中国广电「资费公示」H5（`m.10099.com.cn/costNotice/` /
  `contact-web / queryTariffAllByCond`），约 **324 条**（全国 193 + 河北 131，含已下架 116）。
  🔴 **这家不需要抓包**：它是公开的 H5 公示页，打开 DevTools 就能看到全部接口
  （App 反而抓不到）。且它只有「全国 / 河北省」两级**地区**，两份数据交集为 **0**
  ⇒ **两份都要采**，不是包含关系。
- **电信** —— 中国电信 APP「资费专区」河北
  （`POST www.189.cn/wapportalweb/wapportalweb/tariffSection.do`），约 **884 条**。
  请求体是 **AES-128-ECB** 密文（密钥 `telecom_wap_2018` 硬编码在一份公开 JS 里）。
  🔴 但它的 WAF 是**瑞数类 JS 挑战** —— 纯 HTTP 必 412，而自动化浏览器
  （`navigator.webdriver=true`）会被 400 硬拒 ⇒ 云端靠 **Xvfb + 有头真实 Chrome**
  采集（`probes/tools/ct_browser/ci_grab.sh`，CI 里那一步），采不到才退回仓库快照。

四网合计约 **12994 条**（移动 3887 · 联通 7899 · 电信 884 · 广电 324），
单文件 gz 约 **787 KB**（阈值 900 KB，见「性能」一节）。

## 地域口径（河北省 / 全国 + 地市）与「已下架」（2026-09-22 新增）

**地域**只要「河北 + 全国」两档，每行按**原始地域字段**打标（不是在名称里猜地名，
那会漏掉「名称没写地市」的条目）。另有**条目级地市码** `cty`（空 = 全省通用）。
四网的判据完全不同，见 `tariff_monitor.WHERE_OF`：

| 网 | 河北 | 全国 | 地市（条目数） |
|---|---|---|---|
| 移动 | 2438 | 1449 | **481（12 市全有）** |
| 电信 | 884 | — | **31（12 市全有）** |
| 联通 | 7899 | — | **无** |
| 广电 | 131 | 193 | **无** |

- **地市**取条目自带的 4 位地市码（移动读 `applicableArea`/`city`，电信读归一化时
  特意保留的 `_areaCodes`）；只有条目没有码时才退回**文本兜底**（捞「雄安新区 /
  华北油田」这类没有码的特殊区域）。
- **联通与广电上游没有地市级数据**（联通 `cityId` 只影响能否办理、且 12 城骨架逐条一致；
  广电区域码表只有省级）⇒ 这两网的页面**不出地市这一层**（隐藏，不是置灰）。
- 「—」= 该网公开渠道**没有这一档**，页面上对应的筛选项会**置灰**，而不是让你选完
  得到「0 条」—— 后者是拿一个不存在的维度在问，答案没有意义。
- 与河北无关的（其他省份专属）条目会被**丢弃**，条数写进日志。`probes/probe_scope_state.py`
  是这套判据的离线回归探针（含地市码断言：联通/广电必须为 0、移动/电信必须有），
  改判据后跑一遍看分布有没有突变。

**政企资费**：四网公开接口**全部取不到**（移动 `isPublic=0` 明细恒 0、联通无政企分类、
电信 5 类无政企、广电 `ZQ` 空壳），政企门户也都不公开 ⇒ **当前不做政企层**。
详见仓库根 README 的「政企资费」一节。

**已下架**单独一个页签（不与在售混列，避免污染在售的排序与变更检测）。
判据同样逐网不同，且**只用上游给的信号**（`tariff_monitor.state_of`）：

| 网 | 判据 | 条数 |
|---|---|---|
| 联通 | 归入一级分类 `99`「停售套餐」 | 3092 |
| 广电 | 服务端 `stateFlag != 1` | 116 |
| 电信 | 下线日早于数据基线日 | 0（当前） |
| 移动 | 🔴 **拿不到** —— `isPublic=0` 能列出分类，但明细接口恒返回 0 条 | 0 |

> 🔴 联通那批**不能靠下线日判**：老注释写的「3879 条里 3874 条 `endDate` 已过期」
> 取自当时样本；2026-09-22 实测该批过期条数为 **0**。它被归到 `99` 类这件事本身
> 才是唯一下架证据 —— 所以判据改成分类归属，并且**不再默认排除**该分类。

## 跑

```bash
pip install pycryptodome
printf 'KEY=...\nIV=...\n' > .nrapigate_key    # 只需一次；该文件已 gitignore
python tariff_monitor.py                       # 抓取 ~15s，写快照 + 报告 + 归档页面
python tariff_monitor.py --no-html             # 只要数据，不生成页面
python tariff_monitor.py --render-only         # 不联网：用现有页面数据套当前模板重渲染
```

### 改了 `template.html` 怎么立刻看效果

用 `--render-only`。它**不联网、不写快照、不动 `changes/` 与 `state.json`**，
只把 `docs/index.html` 里已有的那段 `const NETS={...}`（四网容器）抽出来，
套上当前的 `template.html` 重新渲染，再更新 `page/index.html.gz` 归档。
（页面若还是四网改造之前的 `const DATA=[...]` 旧格式，它会自动迁移成容器格式再渲染
—— 否则会死锁：想重建页面得先有新格式容器，而容器只能靠重建才写得出来。）

🔴 **别为了「重建一下页面」去顺手跑一次完整抓取**：完整流程会写快照、写
`changes/<今天>.md` 并覆盖 `state.json`。云端当天已经跑过一轮时，本地补跑会以
「本地那份旧基准」生成一份**不一样的**变更报告，把云端的真实结果盖掉。
只改模板就用 `--render-only`。（`--render-only` 不依赖 pycryptodome，裸环境也能跑。）

### 改了某个 `*_monitor.py`（适配器），想「真采一次但不动快照」

用 `rebuild_offline.py`：移动读当日快照、其余各网读**各自的**本地缓存
（首次或 `--fresh` 真采一次，联通约 20s / 广电约 5s），**只调 `build_html`** ——
不写快照、不写 `changes/`、不动 `state.json`。

```bash
python rebuild_offline.py              # 全部用缓存重建，秒级
python rebuild_offline.py --fresh      # 强制重采「非移动」的全部网并更新缓存
python rebuild_offline.py --fresh cbn  # 只重采广电，其余仍用缓存（改一个适配器时最省事）
```

它和 `--render-only` 的分工：后者用的是页面容器里**已经归档**的那份数据（只换模板，
数据不变）；而改了归一化 / 字段映射之后，必须**重新采一次**才能验证，那时用它。
⚠️ 反过来：**新接入一网时不能用 `--render-only`** —— 它按现有容器重建，
而页面里还没有那网的数据，重建反而会把刚接上的那网弄丢。
⚠️ 缓存 `.unicom_cache.json` / `.cbn_cache.json`（gitignore 里按 `.*_cache.json` 通配）
只是迭代便利，**不是真相来源** —— 正式发布与巡检仍走 `net_round()` 的实时采集 + 快照链路。

云端由 `.github/workflows/tariff-daily.yml` 每天北京时间 **06:00** 自动运行，
网关密钥走 Actions Secret（`NRAPIGATE_KEY` / `NRAPIGATE_IV`），不落代码。

🔴 **改了页面的数据容器格式，必须同步改 workflow 里的「校验页面归档」步骤。**
它按文本解析归档页面（找 `const NETS=`、断言条数与基线），容器一改名它就抛异常；
而它排在「提交数据与页面归档」**之前** —— 于是每天的归档从此不再入库，
整条 workflow 变红，翻日志才发现。四网改造（`c7413fc`）就漏改过一次，2026-09-22 补上。
⚠️ 旧版还在检查 `__DATA__` —— 那是改造前的容器名，模板里早就不存在了，
等于在检查一个**永远不会出现**的字符串；而真正该查的 `__NETS__` 反而没人管
（漏替换会让整页 JS 变成语法错误，这一步却照样报 OK）。现在占位符列表已列全。

### 四网骨架（当前：**四网已全接入** —— 移动 3887 · 联通 7899 · 电信 884 · 广电 324）

```js
const NETS = {
  move   : {sh:"移动", nm:"中国移动", src:"…nrapigate / nrtariff…", base:"2026-09-22",
            rows:[ … ], allProvince:false},
  unicom : {sh:"联通", nm:"中国联通", src:"…mxx.client.10010.com / queryTariffNew…",
            base:"2026-09-22", rows:[ … ], allProvince:true },
  telecom: {sh:"电信", nm:"中国电信", src:"…www.189.cn / tariffSection（真实浏览器采集）…",
            base:"2026-09-22", rows:[ … ], allProvince:false},
  cbn    : {sh:"广电", nm:"中国广电", src:"…m.10099.com.cn / queryTariffAllByCond…",
            base:"2026-09-22", rows:[ … ], allProvince:true }
};
```

- **结构刻意做成对称的**（四家都有 `sh/nm/src/base/rows`），而不是「移动特殊、三家另放数组」
  —— 后者每加一处逻辑都要分叉一次，迟早漏掉一边。
- 点网别入口就切（**同一个页面来回跳**，不跳新页面）；`net` 无条件写进 hash
  （如 `#net=unicom`），分享链接能直达某一网。切到未接入的网显示占位说明，
  并把工具栏 / 统计行 / 表格 / 分页器一起藏起来 —— 给一个点不出东西的工具栏，
  用户只会怀疑页面坏了。
- 🔴 **每网自带一个 `base`（数据基线日期），不是全局共用一个。**
  相对天数与上架 / 下线时间筛选都以**本网**基线为准：三家的抓取时点不可能总落在同一天，
  共用一个基线会让后接入的那几家整体算错天数，而且**不报错**。
  因此 `BASE` 已从常量改成由 `setBase()` 在每次 `apply()` 开头按当前网重算
  （放在 `apply()` 而不是只放在切网函数里，是为了让「直接带 hash 进来」「hashchange」
  这些旁路也一定先重算过）。
- **接入一家要做什么**：把那一家的 `rows` 灌进去，补上 `src`（来源）与 `base`（基线日期），
  页面侧不用改。构建侧只需动 `tariff_monitor.py` 里**两处**：适配器加进 `NET_RUN`、
  快照前缀加进 `SNAP_PREFIX`（`NET_LIVE` 顺带补上）。`net_payload()` / `rows_of()` /
  `build_html()` 都是按 `NETS_META` 循环的，不用改。
  ⚠️ 别把 `net_round()` 复制成 `unicom_round` / `cbn_round` 两份 —— 那等于把
  「骤降保护 / 沿用上次快照 / 基线不覆盖」各写两遍，改一处漏一处时症状是
  **某网静默地不再保护数据**。
- 换网会**清空筛选项**（保留排序键）：类型下拉是**按网重建**的，上个网选中的类型在新网里
  根本不存在，留着 `value` 就会出现「下拉显示『全部类型』、实际按一个幽灵值过滤」的静默错。
  点**当前**网则只刷新、不清筛选（幂等）。
- 🔴 **`allProvince` 声明「本网数据不分城市」**（联通、广电为 `true`）。它不是一个展示开关，
  而是**维度可用性**的声明 —— 页面据此**隐藏**「地市 / 专属区域」整个下拉
  （2026-09-22 起从「置灰」改为「隐藏」：这两网**上游就没有**地市级数据，
  留着空控件只会让人以为是自己选错了）。详见上一节。

### 接入第四网（电信）时踩到的坑（2026-09-22）

- 🔴🔴 **这网的数据必须借真实浏览器采**：API 端点被瑞数类 JS 挑战拦（412，curl 同样 412），
  且 **`navigator.webdriver=true` 的自动化浏览器直接 400 空响应**（连挑战页都不给）。
  唯一实测通路：真实 Chrome 只加 `--remote-debugging-port`（**不加** `--enable-automation`），
  CDP 进页面后用页面自带的 CryptoJS 造包体发请求，响应是**明文 JSON**。
- 🔴 **电信注册 `NET_RUN` / `NET_LIVE`，同时也在 `NET_SNAP` 兜底名单里** ——
  它是「机会性采集」：**采得到就正常走完整轮次，采不到就退回快照渲染**。
  `other_nets()` 先问 `snap_net_ready()`「本轮真拿到采集产物了吗」（判据是产物里
  记的**采集日期**，不是文件在不在、更不是 mtime），是才走 `net_round()`；
  否则跳过，由 `NET_SNAP` 那段用 `load_latest()` 顶上。
  - 为什么不用「文件在不在」判：`.ct_raw.json` 不入库，本机那份可能是上周采的，
    光看存在就走采集，会把一份陈旧数据当今日快照入库、还生成一份假的「无变化」报告。
  - 为什么不用 mtime：CI 每次都是全新 checkout，mtime 恒为「现在」，等于恒真。
  - 🔴 `net_round()` 的 `except` 必须同时接住 `SystemExit`：`ct_monitor.fetch_all()`
    在缺产物时刻意用 `SystemExit` 抛一段给人看的采集指引，只接 `Exception` 的话，
    一次「本轮没采到电信」会把整个巡检打断，连另外三网的页面都出不来。
  - 🔴 电信的 `fallback` 传 `load_latest`（不是默认的 `load_prev`）：本轮没采到时，
    该用**最新那份**快照，而不是「严格早于今天」的那份 —— 否则仓库里明明有今天的数据，
    页面却退回昨天。
- 🟢 **「电信在云端采不到」是错的**（2026-09-22 实测推翻）：Xvfb + **有头** Chrome
  （只给 `--remote-debugging-port`）在 ubuntu-latest 上挑战自动通过、884 条逐项采全。
  之前的判断把「某个做法不行」记成了「那个环境不行」——
  判据要落在**机制**（`navigator.webdriver` 标志位、有没有屏幕）而不是**场所**（本地/云端）。
  详见 `docs/电信云端采集可行性-20260922.md`。
- 🔴 **查询参数 `type=1` 才是「按 lable1Id 过滤」**；type≠1（0/2/3）会忽略 lable1Id
  返回全量 —— 拿它做分类轮询会得到 5 份全同副本。`tariffAttr`(1/2/3) 与过期零相关、
  页面不用；`sessionid` 给空串也放行（服务端下发真值）。
- 🔴 **费用单位不全是月费**（元/次 78 条、积分/次 43 条…共 382 条非月费口径）：
  归一化时这些行的月费 `f` **留空**、费用原文并进详情 ——
  否则月费筛选会把「充100元返100元」当成月费 100 元。页面搜索/类型筛选不受影响。
- 省份码硬编码在页面组件 `Index-1f2bc0ae.js`（河北=609906、北京=609001、集团=1000000037）。

### 接入第二网（联通）时踩到的坑

接口家族、零凭证特性、`cityId` 无关性的实测依据，见 `probes/he_unicom_tariff.py` 的
文件头与 `cloud/tariff/unicom_monitor.py`。这里只留「不知道就会踩」的几条：

- 🔴🔴 **别把「参数能传」当成「数据按它分」。** 联通的 `indexData` / `threeLevelName` /
  `operateData` 都接受 `cityId`，但实测换城市拿到的三级菜单与明细**逐条相同**
  （抽查两个组合：石家庄 / 邢台 / 唐山 = 77/77/77 与 39/39/39 全等；
  全量 8978 个三级菜单、去重后 7899 条明细 —— 其中 3092 条属一级分类 `99`「停售套餐」）。
  它压根没有「属于哪个市」这个属性。于是用移动那套「从名称文本里猜地市」的
  `cityTags()` 去筛联通，**选任何地市都是 0 条**：一个看着像正常结果、
  实则是拿一个不存在的维度在筛的**虚伪陈述**（跟「邢台真的没有资费」是两件事）。
  修法是三件事一起做：
  1. 让**数据源自己声明** `allProvince: true`（在 `unicom_monitor.fetch_all()` 里写死，
     而不是从文本猜）；
  2. 页面 `renderDims()` 据此把地市选项 `disabled` 并在控件 `title` 上写明原因；
  3. `readHash()` **拒绝把本网不可选的取值写进控件**（`#net=unicom&ct=邢台` 这样的
     旧链接 / 别人转发来的链接，否则打开就是白页），`apply()` 里再留一道保险丝
     兜住程序化赋值（实测 `select.value="邢台"` 对 `disabled` 的 option **仍会成功**）。
     口径统一为「**无效筛选 = 不筛**」，而不是筛出 0 条。
  对照：本网当天「本次变更」0 条**是真的 0 条**，所以那项只改标签文案（「（本网无）」）
  而不禁用 —— 两处的差别就在「0 条是真是假」。
- 🔴 **快照必须分前缀。** `load_prev()` 按文件名排序取最近一份，两网混放会让**联通昨天的**
  快照变成**移动今天的**基准 —— 变更检测随即凭空报出「新增几千 / 下线几千」。
  故 `SNAP_PREFIX = {"move": "hebei_tariff_", "unicom": "unicom_tariff_",
  "cbn": "cbn_tariff_", "telecom": "ct_tariff_"}`，`load_prev` / `save_snapshot` /
  `prune_snapshots` 全部加了 `prefix` 参数。**加一网就得加一行前缀** ——
  `render_only()` 也是拿它的 key 当「已接入网」清单在枚举的，漏一行就等于那网在页面重建时被丢掉。
- 🔴 **任何一网失败都不该拖垮其它网。** `net_round()`（非移动各网共用一份）在采集异常 /
  数据骤降时沿用上一版快照继续渲染，绝不因此让整页出不来 —— 新接一网时上游不稳是常态，
  而「多网共用一个页面」意味着任何一网抛异常都会让其它网也看不到。
- **每个源的字段名不同，在适配器里归一。** `unicom_monitor.normalize()` 把
  `feesStandard→fees`、`commonData→data`、`minute→call`、`useScope→applicablePeople`、
  `saleChnl→channel`、`startDate→onlineDay`、`endDate→offineDay`、`broadBand→brandwidth`
  映射成移动那套；广电那份在 `probes/he_cbn_tariff.py` 的 `normalize()` 里做同样的映射
  （`productPrice/100→fees`、`domesticTraffic→data`、`filingNumber→reportNo`…）。
  于是各网共用同一条渲染与变更检测链路（`rows_of` / `index_rows` / `diff_rows`），
  页面行字段（18 个）三网完全一致。
- 🔴 **`index_rows()` 的 `ty` 口径必须与 `rows_of()` 逐字一致。**
  原来是 `ZFLX.get(g["type2"], "?")` 硬查移动那张码表 —— 移动对得上、联通 1..5 恰好同义，
  而广电的 `type2` 是 `GZ_TC_5G` 这种代码、`ZFLX` 里根本没有，于是
  **变更报告里的种类名全显示成 `?`**（页面却正常，因为 `rows_of` 走的是
  「`type2Name` 优先」）。现统一成 `g["type2Name"] or ZFLX.get(type2) or "?"`。
  两处口径不一致是接第二网时就埋下的，接第三网才暴露 —— 这类「同一份数据两条取值路径」
  的地方，改一处就要顺手对一眼另一处。
- 🔴 **「停售套餐」要采，而且不能靠下线日判它。** 2026-09-22 修正：老说明称
  「3879 条里 3874 条 `endDate` 已过期（99.87%）」——**该结论已不成立**，
  当天实测这一级的 `endDate` 过期条数为 **0**。所以：
    · 判据改为「它被归到一级分类 `99`」（`tariff_monitor.state_of`），
      这是唯一下架证据；靠日期判会把 3092 条在售/停售混杂的判断整体做错。
    · 采集**默认包含**该分类（`include_stopped=True`），进页面的「已下架」页签，
      不再与在售混列 —— 既收全了，也不污染在售的排序与变更检测。
  （历史原因：初版为与移动 `isPublic=1` 保守对齐而默认排除，属**证据变更后未回看**的典型。）
- **`operateData` 的 URL 就是一批三级 id 用 `_` 拼串**，且 `size` 由客户端控制
  （JS 里是 `level3.slice((page-1)*size, page*size).join("_")`）——
  默认 5 会让请求数上百，调到 20 后降到 265 次。
- ⚠️ `collect()` 开头有一项**前提抽查**（`city_drift()`）：随机挑两个组合、
  比三个城市的三级菜单条数并打印。上游哪天改成**真的**按城市分数据，
  「只采一城」就会**悄悄丢数据** —— 这项抽查是唯一的报警器，别删。
- ⚠️ 同族接口里 `cityList` 的参数名是 **`provinceCode`**，其余都是 `provinceId`；
  传错回 `{"code":"0001","desc":"参数错误"}`。而 `0001` + `msg="当前目录下暂无资费信息"`
  是**正常空目录**、不是错误 —— 别把它当失败重试。

### 接入第三网（广电）时踩到的坑

接口家族（4 个端点）、`access` 头、地区语义的实测依据，见 `probes/he_cbn_tariff.py`
的文件头与 `cloud/tariff/cbn_monitor.py`。这里只留「不知道就会踩」的几条：

- 🟢 **这网不需要抓包。** 它是公开的「资费公示」H5（`m.10099.com.cn/costNotice/`），
  打开 DevTools 就能看到全部接口。**App 反而抓不到** —— 实测 Fiddler 里
  `app / m / partner.10099.com.cn` 的请求有两百多条，**全部**止步于
  `Proxy Configuration Script specified an unreachable proxy`，一条会话都没落下。
  以后遇到同类需求：**先找公示页，再考虑抓 App。**
- 🟢 **`access` 请求头实测不被服务端校验**（2026-09-22 对照实验更正：
  `43a62542…` / `0106765e…` / App 的 `256364cd…` / **完全不带**，四组 × 2 端点 × 2 区域
  全部 HTTP 200 + status=000000，条数逐一致 —— 抓包里出现三个不同值就是它不被校验的旁证）。
  脚本仍发送旧常量（无副作用），但**别把它当凭证**、也别在它变化时报警。
  对 `status != "000000"` 一律**显式报错**（fail-closed）这条要保留，只是理由改一下：
  防的不是 access 失效，而是**上游哪天改协议/改口径导致静默采空** ——
  空列表会被下游当成「今天资费全下架了」，既报出一批假变更，又没人发现管道已经断了。
- 🔴🔴 **`applicableArea` 是真的分级，而且两级交集为 0。**
  `ZZZZ`（全国）204 条全标 `areaNames="全国"`、`HB00`（河北）131 条全标 `"河北省"`，
  逐条比对**交集 = 0** ⇒「河北用户能办的」= **全国 + 河北 两份都要采**，少采一份就少一半。
  （对照联通：那边是「一份数据换个城市还是它」；这里是「各是各的」。）
  探针里有 `check_area_split()` 每次抽查这个前提 —— 上游哪天改成包含关系，
  两份相加就会**静默翻倍**（变更检测一口气报出上百条新增，而没人会想到是地区语义变了）。
- 🔴 **价格单位是「分」**：`productPrice=1000` + `productPriceUnit="月"` 就是

- 🔴 **`type1` 必填但值被服务端忽略**：传 `GZ` / `ZQ` / `1` / `2` 返回条数**完全相同**
  （河北一律 131）。别按 type1 分别采 —— 那只会得到两份全同副本。只有 `type2`/`type3`
  真能过滤。这与联通「参数能传但数据不分」是同一类陷阱的另一面：**这里反过来，
  参数必填但没用**。
- **在售口径用服务端状态位** `stateFlag == "1"`（与移动的 `isPublic=1`、
  联通的「排除停售套餐一级」对齐），别自己解析日期。

  两个信号不总一致，以状态位为准。
- ⚠️ **日期是 `2024年09月27日`，必须转成 `20240927`** —— 页面 `toDate()` 只认
  `^\d{8}$`，不转就被 fail-closed 过滤掉，时间筛选会**静默少数据**。
- ⚠️ **字段名撞车**：广电把「套外资费」放在 `tariffAttr`（如「套外国内流量3元/GB…」），
  那正是移动 `extraFees` 的语义。**它不是分类号** —— 别拿它占页面行的 `a1` 列。
- ⚠️ **两级菜单有重名**：`GZ_TC_KD` 与 `GZ_TSQTTC_KD` 都叫「宽带」

  所以 UI 上「宽带」仍只出现一次、勾上后两类都命中 —— 这正是想要的。

### 页面怎么找资费

- **排序**：点任意**表头**按该列排（再点一次切换升降序），箭头 `▲▼` 显示当前列与方向；
  也可用「排序字段」下拉 + 右侧 `↑/↓` 按钮。空值恒排最后，不受升降序影响。
- **按新上架**：`上架时间` 筛选项（7/30/90/180/365 天内、或无上架日期）；
  快捷 chips 里 `7/30/90 天内上架`。近 30 天内的新资费标 `NEW`，未来的标 `待上架`。
- **按临期**：`下线时间` 筛选（30/60/90 天内到期），60 天内标橙、已过期标红、10 年以上标「长期」。
- **按城市**：`城市` 下拉 —— 11 个地市 + `雄安新区` / `华北油田` + `全省通用（未限定地市）`；
  判定口径见下方 ⚠️。
- **其他**：关键词、类型、月费区间、宽带、城市；`重置` 一键清空。
- **条件同步进 URL**（如 `#net=move&pf=0,0&s=fee&d=1`），刷新或分享不丢；刷新后直接还原。
- ⚠️ **「含宽带」的判定口径 —— 别只看 `brandwidth` 一个字段，那样必错**：
  该字段既不干净也不完整。**假阳性**：116 条填的是 `0` / `-` / `无` 这类占位符，
  只看「非空即含」会把视频彩铃、和家固话、副卡功能费都算成含宽带；
  **假阴性**：真含宽带的「河北移动1000M融合宽带」「动感地带芒果卡（宽带版）」
  等 36 条该字段反而是空的。所以页面用**「字段值 + 名称」两条腿**，
  并剔掉只是宽带**服务**的条目（提速包 / 光网组网 / 装机 / 调测 / 检修 / 宽带电视 IPTV）。
  结果（按 2026-09-22 数据实测）：`含宽带` **91 条**、`宽带提速 / 光网组网` **243 条**。
- ⚠️ **「城市」的判定口径 —— 数据里根本没有城市字段，四个文本字段缺一不可**：
  地市只能从 `tariffName` / `套餐名` / `目标客户` / `权益说明` 里认字面地名。
  **只看名称会漏 46 条**（地名写在「目标客户」里的「移动云盘2026特惠季包」→秦皇岛、
  「全承游电视增值包」→承德、「权益金会员180元档」→保定）；
  **只看「目标客户」会漏 103 条**（市级包名带地市、但该字段只写通用话术
  「河北移动用户」的「邯郸179元低消回馈」「秦皇岛10元语音低消」「石家庄数字生活特权季包」）。
  所以取四字段**并集**。结果（按 2026-09-22 实测）：命中任一城市 **373 条**；
  `全省通用`（四字段都没提地市）**3505 条** —— 注意它**不等于「全部城市」**，
  多市条目不算全省通用。
  一条可属多市（IPTV 类在目标客户里列了 4 个市；「沧州华油尊享礼包」同属沧州与华北油田），
  它在**每个**对应城市的筛选里都会出现 ⇒ 各市条数**相加 ≠ 373**。
  唯一的措辞冲突：「全省校园资费-1元畅玩包」名写全省、目标客户却限石家庄 ⇒ 按实际限制归石家庄。
  子串误命中已逐条排查（把每处命中的上下文都过了一遍），未发现把别的词当地市的情况；
  「权益」字段目前贡献 **0** 条独有命中（凡命中它的，名称或套餐名必已命中）。
- **看「本次变更」**：顶部摘要后面挂一条**变更明细链接**（直达仓库 `changes/<日期>.md`）；
  变更过的行在名称旁标 `新增` / `变更` 徽章（点开详情行还有一行说明）；
  `本次变更` 下拉 / 快捷 chip 可以只看这批。链路见下节。
- **导出与留存**：`导出 CSV` 导的是**当前筛选结果的全部**（不是当前这一页 —— 否则 49 页
  得点 49 次），带 BOM（不加的话 Excel 按本地代码页解读 UTF-8，中文全乱码）；
  `保存本页` 把整页另存为**单文件离线 HTML** —— 数据是构建时写进页面的，
  存下来不联网也能直接打开。两者文件名都用「数据基线日期」而不是当前时刻，
  同一份数据导两次得到同一个文件名，不会堆出一堆看着不同、其实一样的副本。
- **每元流量**：既是排序键（下拉里的「每元流量」），也显示在「流量」列下方的小字里 ——
  否则按它排完序，页面上根本看不到排序依据的那个值。
  0 元且含流量的套餐（按 2026-09-22 实测 **227 条**，占「有流量」条目的三成）
  每元流量是 `∞`，**排在最前**，而不是当空值沉到最底。
- ⏱ 「上架 / 下线」的天数以页面顶部的**数据基线日期**为基准，不是打开页面的当天
  —— 页面里必须没有任何运行时刻，归档的逐字节去重才能生效。

### 本次变更信息是怎么走到页面上的

`diff_rows()` 每天都算出三段明细（新增 / 下线 / 字段变更），但很长一段时间里，
只有「新增 N 条 · 下线 M 条 · 字段变更 K 条」这一句进了页面 ——
**哪几条、变了什么**只存在于 `changes/<日期>.md`，页面上看不到、也点不过去。现在补成三段：

1. **摘要带链接**：`main()` 把当天报告在仓库里的地址拼进 notice。
2. **行级标注**：`build_html(…, diff=…)` 给命中的行写 `ca`（本次新增）/ `ck`（关键字段变更）。
3. **页面可筛**：`本次变更` 下拉 + 快捷 chip（本网当天无变更时 chip 自动收起，选单保留 ——
   万一地址栏带着 `chg=1` 进来，状态仍然可见、语义仍一致，而不是被悄悄抹掉）。

🔴 **行级标注的键必须与 `index_rows()` 逐字一致**：取**未截断**的 `name`
（`name` 缺失时退回 `tariffName`），重名追加 `#2` / `#3`。
图省事拿页面里那个**截断到 120 字符**的 `n` 去比，超长名字会**静默对不上** ——
要么标错行、要么一个都不标，两种都不报错。

🔴 **`_mark_changes()` 带条数自检，对不上就整批撤标。**
标注**错行比不标更坏** —— 用户会据此认定某条资费变了。宁可退回「没有标注」，
也不留一批看着像真的、其实指错行的标注。

⚠️ `diff_rows()` 的 `changed` 是 `[(键, {字段: (旧, 新)})]`，取键要展开
（`{k for k, _ in c}`）。直接 `set(c)` 得到的是一堆元组，一个都匹配不上，
然后被上面那道自检兜住 —— 所以自检也是这类手误的兜底。

⚠️ 标注依赖「上一版快照」，所以 **`--render-only` 不会重算标注**，它只保留页面上已有的
（从容器里原样读出来再写回去）。这是对的：重渲染不该改变「今天变了什么」的结论。

### 页面的容错约定（fail-closed，不是 fail-open）

- **基准日期坏了 ⇒ 时间筛选一律「不通过」，而不是「忽略该条件」。**
  页面顶部会弹红色警告条，上架/下线列只显示日期、不显示相对天数。
  理由：`BASE` 一解析失败，`ago/left` 全变 NaN，而 `NaN<0 || NaN>7` 恒为 false
  ⇒「7 天内上架」会**静默返回全部条目**（移动那网 3887 条）：不报错、看着还挺正常，
  这是最坏的一种错。
  构建侧 `tariff_monitor.py` 的 `data_day()` 也会先拦一道，回退到**稳定的快照日**并打警告
  （不能用「今天」当回退，那会让页面内容天天变、归档逐字节去重失效）。
- **日期必须是真实存在的日历日。** `20260230` 这种「8 位数字但日历上没有」的值会被 `toDate()`
  拒绝 —— 否则 `Date.UTC` 会把它**静默归一化**到 3 月 2 日，相对天数与时间筛选整体偏移。
- **宽带列排序**：判为含宽带、但名称与字段都没写速率的那几条（如「动感地带芒果卡（宽带版）79元档」）
  用哨兵值 `-1` 参与排序，使其**留在宽带组内、排在已知速率之后**，
  而不是混进几千条「不含宽带」的空值尾部里彻底看不出（真速率都 ≥100，-1 无歧义）。
- **切到未接入的网时，工具栏 / 统计行 / 表格 / 分页器不只是「藏起来」，内容也一并清空。**
  只藏不清的话，DOM 里会留着**上一个网**的旧统计行与旧表格行，「看不见」和「没有」
  就变成两件事 —— 之后任何读 `#stat` / `#tb` 的代码（包括体检脚本）都可能拿到残留值。
- **改了 URL 的 hash 会立即生效**（监听 `hashchange`）；`syncHash` 用的是 `replaceState`
  （不触发该事件），所以不会自激循环。
- ⚠️ **`readHash()` 是「合并」语义，不是「全量替换」**：hash 里**没写**的参数保持当前值，
  不会回到默认。页面自己生成的链接永远是完整状态（`syncHash` 无条件写全），所以正常使用
  不受影响；只有**手敲半个 hash** 时要注意 —— 想清掉某项得显式写空
  （如 `#net=move&chg=&ct=唐山`）。这与上面那条「非法枚举值视作没传」是同一条规则。
- **hash 里写页面不认识的枚举值 ⇒ 视作「没传这个参数」**（控件回到「全部」、结果回到全量）。
  不核对就赋值的话，`select.value` 会**静默失败**：下拉停在「全部城市」、代码却按那个
  幽灵值过滤 —— **控件与结果对不上，还不报错**。`syncHash` 随后会把非法参数从地址栏抹掉，
  链接自愈。（实测过的口径分叉：`ct=火星` / `ty=nope` 静默变成 0 条，
  而 `pf=abc` / `on=99999` / `bw=nope` 静默变成「不筛」—— 同一类输入两种相反结果，
  所以统一成一条规则。）

### 性能：排序为什么会快一个数量级

≈3900 行实测（Chrome，9 次取中位数；测量时移动那网 3878 条，量级未变）：

| 操作 | 改前 | 改后 |
|---|---|---|
| 只排序（按上架时间） | 33.5 ms | **3.9 ms** |
| 只排序（按名称） | 19.6 ms | **10.5 ms** |
| `apply()` 全流程（默认排序） | 40.6 ms | **12.6 ms** |
| `apply()` 全流程（按名称） | 29.1 ms | **21.9 ms** |
| 渲染 80 行 | 6.6 ms | 7.4 ms |

- **病灶**：`Array.sort` 的比较函数会被调用约 n·log₂n 次（≈3900 行约 **4.6 万次**），
  而原实现在**每次比较里现算取值** —— 等于把 `toDate()`（正则 + `Date.UTC` + 回读校验）
  和 `localeCompare()` 各跑 4.6 万次，而取值本身只要 **0.5 ms**。
  改成**装饰-排序-反装饰**（先各自求一次值、再比「值」）后，取值次数从 O(n·log₂n) 降到 O(n)。
- **`localeCompare(y,"zh")` 每次调用都要重新解析 locale、重算排序键**，
  换成模块级 `Intl.Collator("zh")` 复用同一个实例。
- 语义**必须不变**：空值恒排最后、方向由 `sortD` 决定、V8 的 `sort` 是稳定的
  （相等元素保持原相对顺序）。验收方式就是「同一批数据 × 9 个排序键 × 2 个方向，
  与旧实现逐项比对」—— 18 组**逐项完全一致**才算过。
- 顺带：`cmpX()` 里加了 `if(x===y)return 0`。这不是优化，是**正确性** ——
  两个 `+∞` 相减是 `NaN`，而比较器返回 `NaN` 属实现定义行为。

### 两处「看起来该做」但实测否决的优化

记在这里是为了别再有人走一遍：

1. **共享字符串池**（把 `vp` / `ch` / `ap` 这些重复值抽成字典 + 下标引用）：
   原始体积 1329 KB → 1077 KB（**-245 KB**），但 gzip 后 245.3 KB → 247.9 KB
   —— **反而多了 3 KB**（下标数字本身要占字节）。gzip 已经吃掉了这份冗余，
   改它只会给五个文件平白加上耦合。**否决**。
2. **删掉模板从不读的僵尸字段** `d`（流量原文）/ `du`（流量单位）/ `a1`：
   原始体积 -99 KB，gzip 只 **-4 KB（-1.6%）**。收益可以忽略，
   而 `a1` 还是行级变更标注的 join 键之一，删了要另找键。**否决**。

结论：**实际传输字节由 gzip 决定，别拿原始体积下判断。** 想知道真要下多少，
看构建日志里那个 `gz` 数字（构建脚本现在会打出来，超过 `GZ_WARN` 还会提醒）。
**四网全量实测 787 KB gz（12994 条 / 原始 8.4 MB）** —— 比四网改造初期（9776 条 /
6.26 MB / 564 KB gz）多出的部分几乎全来自联通那 3092 条停售资费。
⚠️ 787 KB 已经逼近 `GZ_WARN` 的 900 KB 预警线：**再接入一网或再放开一个维度，
就该按网拆分 / 按需加载了**，而不是继续往单文件里塞。

## 数据体检（改完模板 / 巡检后可跑）

```bash
python audit_data.py          # 体检并断言，有异常时退出码 1
python audit_data.py --quiet  # 只看结论
```

页面的筛选/排序判断写在前端 JS 里，而源字段有脏值 —— 判据写松了会**静默**多算或少算，
翻几千行是看不出来的。这个脚本把判据在 Python 侧复现一遍，算成具体条数：

0. **页面元信息**：顶部「数据基线日期」必须是可解析的**真实日期** —— 它是页面全部相对天数与
   上架/下线时间筛选的基准，坏了会让那些筛选**静默失效**。
   （四网之后每网各一个基线，页面运行时按当前网取 `NETS[net].base`。）
1. **字段格式**：`onlineDay` / `offineDay` 须 8 位数字**且是真实日历日**；月费/通话须纯数字；
   流量单位是否都被 `gb()` 覆盖。
2. **宽带判定**：复现 `bwInfo()`，报告「判为含宽带的条数 / 旧口径会误算的条数 / 可能被排除词误伤待人工过目」。
3. **流量换算**：`d + dataUnit → g` 是否自洽，**并拦 NaN / Inf**
   —— `abs(nan - nan) > 1e-6` 恒为 False，只比差值会静默放过，
   而页面会把它渲染成「NaNMB」这种字面垃圾。
4. **搜索覆盖面**：页面搜索字段集 vs 含 `d`/`du` 的全字段，列出「搜不到」的缺口。
5. **城市判定**：复现 `cityTags()`，报告各市条数、全省通用条数、多市条目、**字段来源组合**
   （`--AP-` = 地名只在目标客户里 ⇒ 只看名称会漏；`NT--` = 目标客户是通用话术 ⇒ 只读该字段会漏）、
   以及每市命中的上下文抽样（人工过目有无假阳性）。
6. **规则同步**：校验 `audit_data.py` 与 `template.html` 的 `BW_BADVAL` / `BW_NOTLINE` /
   `CITY_LS` / `CT_ALIAS` 是否一致。

⚠️ 改 `template.html` 里的 `BW_BADVAL` / `BW_NOTLINE` / `CITY_LS` / `CT_ALIAS` 时
**必须同步改 `audit_data.py` 的同名常量**，第 6 项就是用来拦住「只改一边」的。
体检**只断言结构性不变量**（城市表无零命中、常量与模板同步），不写死具体条数
—— 条数随上游数据每天变，写死必假警报。

## 与页面对账（改了筛选/排序逻辑后做一次端到端验收）

⚠️ **这两个脚本都只覆盖【移动】那一网**（`audit_data.py` 的 `NET_LIVE = "move"`，
`conformance.py` 经它取数）。联通 / 广电**不在**对账范围内，且不是疏漏 ——
这两家都没有地市维度（联通与 `cityId` 无关、广电只有「全国 / 河北省」两级地区），
硬套移动那套 `city_tags()` oracle 只会产出「邢台 N 条」这种与页面
（联通在售 4807 条）正面矛盾的期望值。
联通 / 广电侧验收 = 浏览器逐项实测 + CI 的**逐网**容器断言
（`.github/workflows/tariff-daily.yml` 里的
`LIVE = {'move': …, 'unicom': …, 'cbn': …}` 循环）。
⚠️ 各网量级不同，**条数下限要逐网给**：广电只有两百来条，照抄 500 会让 CI 天天红；
而一旦为此把全局下限压到 100，移动 / 联通那两网的真骤降就再也拦不住了。

`audit_data.py` 只体检**数据**；页面**行为**是否与设计一致，用 `conformance.py` 对账：

```bash
python conformance.py                 # 生成 cases.json（默认写系统临时目录）
python conformance.py out.json        # 指定路径
```

它照**语义独立重写**一套筛选口径（拿页面验页面等于自己验自己），枚举 100+ 用例：
每个筛选项的每个取值（值从数据动态取）× 两两/三重/四重组合 + 必然为 0 的边界。

拿到用例后，把产物与 `cases.json` 放进一个只含这两份文件的目录、起本地服务：

```bash
mkdir -p /tmp/servetest && cp docs/index.html /tmp/servetest/index.html && cp out.json /tmp/servetest/cases.json
cd /tmp/servetest && python -m http.server 8123 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8123/index.html，页面里 fetch('/cases.json') 逐条比对
```

⚠️ `file://` 下 `fetch` 会被 CORS 拦，所以走同源 HTTP；**服务只 bind 127.0.0.1**。
⚠️ 拷贝前 **md5 校验**与真产物字节一致，否则验的是另一个文件。

浏览器侧除 100+ 用例对账外，还应逐项验：排序单调性与空值恒最后、分页边界、
详情展开、快捷标签、重置、空结果、URL hash 双向与非法值、XSS 转义、控制台零报错。
真实数据覆盖不到的分支（如「今天上架」「已过期」）要用**合成行注入**打出来，
含临界点两侧（30/31、60/61）。方法细节见技能 `single-file-html-page-audit`。

「本次变更」这套另需：**标注条数自检**（故意传一个对不上的 diff，断言标注被整批撤掉、
日志里有警告）、筛选后结果确实全部带标、**切网后该筛选项被清空**、
导出 CSV 的列数与转义（造一个含逗号 / 引号 / 换行的字段）、
离线副本能 `file://` 打开且控制台零报错。

⚠️ 判 CSV 行数要拿 `view.length` 比，**不是 80** —— 它导的是全部筛选结果。
⚠️ 判离线副本大小注意 **JS 字符串按 UTF-16 计、文件按 UTF-8 字节计**
（中文 1 字符 = 3 字节）：用 `new Blob([t]).size`，别用 `t.length`，
否则会看着像「少了一半」而误判。

四网部分另需：导航条渲染与选中态、切网后标题/来源/条数/类型下拉联动、
**每网基线各自重算**（往某一网注入同一批 rows 但换一个 `base`，断言两网结果确实不同 ——
否则这个用例没有判别力）、本网 `base` 坏掉时 fail-closed、点当前网幂等、换网清筛选。
⚠️ 断言时**别按插入顺序索引表格行**：`apply()` 会按当前排序重排，要按行名/唯一字段定位。
