数据说明与口径

数据为运营商报备公示口径；「目标客户」为原文条件，能否办理需以营业厅 / 客服为准。 每日 06:00（北京时间）自动巡检， 源码与变更记录见 GitHub 仓库。

本页功能

  • ★ 收藏关注：条目名称前的星标把这条资费收进本机收藏；筛选条上的 「☆ 只看收藏」只显示收藏项。收藏存在浏览器本地（localStorage）， 不上传；可用筛选条上的「收藏导出 / 收藏导入」把收藏备份成 JSON 或搬到别的设备（导入按合并处理，不覆盖本机已有的）。
  • 同价位更优：展开任意一条资费的详情，会自动列出同网 ±10 元档内、流量更多且每元流量更高的在售资费（最多 3 条）—— 省去手动翻几千条比价的过程。
  • 离线安装（PWA）：在浏览器菜单里「添加到主屏幕 / 安装应用」可把本页 装成一个独立应用；断网时能打开上一次缓存的版本（页面本身仍是网络优先， 保证看到的不是昨天的价目表）。
  • 在架规模趋势：「变化历史」页顶部按网画出每天在架条数的折线 —— 哪一网在涨、哪一网在缩，不用逐天点开时间线就能看出。
  • 深色 / 浅色主题：右上角开关切换，默认跟随系统；手动选过后记住选择。
  • 源码包：下载源码快照 —— 可直接跑的一份代码（不含任何凭据与数据快照，由 cloud/tariff/make_source_zip.py 确定性打包）。

来源

    地域口径（河北省 / 全国 + 地市）

    按各网原始地域字段判定（不是从名称里猜地名）：移动看 applicableArea / city / province， 电信看 applicableArea，广电看 _areaNames。与河北无关的（其他省份专属）已按需求剔除。

    地市按各网各自的判据取条目级适用范围，全在构建期算好：

    • 移动：条目自带的 4 位地市码（12 市实测命中 1974 次）； 极少数没有码的（如「雄安新区」「华北油田」）用文案兜底（名称 / 套餐名 / 目标客户 / 权益四字段并集，实测再捞 373 条）。
    • 电信：条目自带的 4 位地市码（实测 265 次）。
    • 联通：按 12 个地市逐城取资费目录并集后，每条资费都带回 「目录里出现在哪些城市」。覆盖全部 12 城的即为「不限地市」（全省通用）； 只出现在部分城市的算「地市专属」（如沧州「华油专属」、雄安「雄安工地0元50G流量包」）。 已下架的那批不算：它们的目录归属是各城遗留清单的差异，不可信。
    • 广电：上游只有「全国 / 河北省」两档（区域码表无地市级，传地市码回 BASE102）⇒ 该网不出地市这一层（隐藏，不是置灰 —— 置灰会让人以为「本网暂时没有」，而真相是上游根本没有这个维度）。

    下拉里的地市 = 11 个地级市 ＋ 雄安新区 ＋ 华北油田。 上游没有给「定州 / 辛集」独立的地市码（逐码单独出现的条目里一条都没有）， 这两个地方的数据并入保定 / 石家庄。早先页面里那个「省直辖（定州/辛集）」档位是 把雄安的码认错了：4 位码 3121 实测就是雄安新区 —— 该码单独出现的 8 条资费里 7 条名字直接写着「雄安」（雄安新区咪咕融合权益包、 雄安9元返费优惠、雄安公交出行权益包…），其余 11 个码单独出现时名字里也各自写着 自己的城市名，只有它对不上。修正后「雄安新区」档才拿到自己的资费。

    「全省通用」有两种上游写法，都已识别：① 地域字段留空； ② 把全部 12 个地市码都列出来（实测 59 条，多是「0预存5G金币购机合约活动」 这类全省活动）。第二种以前被当成了「12 城专属」——于是它既不在「仅全省通用」档里， 又被计进「地市专属」总数。（电信那批只列 10~11 个码的不是全省 —— 它们确实只限那几个市，属正常。）

    哪一网有没有地市这一层，由数据本身决定（本网有没有条目带地市归属）， 不看任何「本网不分城市」的声明 —— 联通那网曾经就是这么被藏掉的：声明与数据不符时， 页面信声明、不信数据，而整个过程没有任何提示。

    「城市」与「地域」是两个维度，别混：地域是省级口径（河北 / 全国， 决定这条资费是不是给河北用户的）；城市是条目级适用范围（这条资费限哪几个市）。 一条「河北省」的资费完全可能同时限定「仅邢台」。

    按地市筛的语义：选某个市 = 「不限地市」的那批 ＋ 该市的专属资费， 也就是「这个市能办什么」。想只看不限地市的那批，选下拉里的 「仅全省通用（不限地市）」。 （早先的口径是「只留地市归属里含该市的」—— 那回答的其实是「哪些资费的上游目录里 恰好写了这个市」。用户按「邢台」筛会得到 9 条、全部停售，于是得出「邢台在售一条都没有」， 而邢台实际能办的资费全在「不限地市」那批里被排除了。2026-09-24 更正。）

    已下架条目不参与地市归属：那些「停售目录」是各城各自的遗留清单，同一条停售 资费被哪些城市收录并不固定（实测 139 条「城市专属」里 18 条其实是 9~11 城共有， 含 6 条明摆着是「…-河北省版」的省版资费）。所以已下架条目只在「全部城市」下可见， 选具体地市时不会混进来；「已下架」页签下地市下拉整体禁用。

    归属（个人 / 政企）

    按官方接口条目的归属字段归一（上游 type1：1=个人资费、2=政企资费）。 四网里只有移动官方标注了归属，联通 / 电信 / 广电的条目里连这个字段都不存在 ⇒ 这三网的「归属」下拉隐藏。 这是上游字段口径，不是从「目标客户」文本里猜的 —— 后者会把「中国移动用户（不含港澳台）」这种 没写明客户类型的大批量条目判成未知（实测占比 84%~99%），撑不起一个筛选维度。

    类型（两级 + 四网同名）

    四网的原始分类本来不同构 —— 广电那网根本没有「套餐」这个词（它写「5G套餐」「流量包」「语音包」）。 所以由构建脚本按 TYPE_CAT 归一成统一大类（套餐 / 加装包 / 营销活动 / 标准资费 / 宽带 / 港澳台-国际）后写进行数据， 页面只读不算。选了某个大类后，不属于它的细分项会置灰，免得选出「套餐 ＋ 加装包」这种不存在的组合。

    渠道

    同样做了归一（线上 / 线下 / 线上+线下 / 其他）：上游原文极碎，光移动一家就有 8 种写法表达「线上」。 四网合计 99.6% 能归上，剩下的原文没写明，一律落「其他」（不猜）。

    数值与时间

    月费 / 流量 / 通话 / 宽带速率四档区间都按数值卡（流量已按 dataUnit 归一为 GB）； 「无流量 / 无通话」含两种情形 —— 填 0 的，和压根没填那个字段的。

    上架 / 下线天数以各网自己的「数据基线日期」为基准，四网各自一个、不跨网共用 （数据没变，页面就逐字节一致，便于归档去重）。基线一旦解析失败，时间筛选会整体停用（fail-closed）并给出可见警告 —— 绝不放行成「全部通过」那种看不出来的错。

    「已下架」页签

    判据各网不同，且只用上游给的信号：联通＝归入一级分类「99 停售套餐」（不能靠下线日判，实测那批一条都没过期）； 广电＝服务端 stateFlag≠1；电信＝下线日早于数据基线日； 移动公开接口取不到下架数据（isPublic=0 能列出分类但明细恒返回 0 条），故该网「已下架」页签置灰。
