# 河北四网资费每日巡检

🟢 **在线查询页：<https://starrry365.github.io/hebei-tariff-monitor/>**

每天 06:00 自动抓取**河北移动 / 联通 / 电信 / 广电**的公开资费（在售 + 已下架），
共一万四千余条，只保留「河北 + 全国」口径；比对上下线变更后重新部署查询页 —— 打开就是最新数据。

页面可按地域、资费类型、渠道、归属（个人 / 政企）等维度筛选，并保留每日变更历史。

代码与运维说明见 [`cloud/tariff/`](cloud/tariff/)。

## 本机改完代码怎么发

一条命令完成「推送 → 触发一轮巡检 → 盯到跑完」：

```bash
tools/push-and-run.sh              # 推当前 HEAD → 触发 → 等结果并打印逐步骤状态
tools/push-and-run.sh --no-watch   # 只推 + 触发，不等
PROXY=http://127.0.0.1:7890 tools/push-and-run.sh   # 换代理
```

> **为什么需要这个脚本，而不是推上去就自动跑？**
> 工作流的 `on:` 只有 `schedule`（UTC 22:00 = 北京 06:00）+ `workflow_dispatch`，
> **刻意没有 `push`** —— 因为每轮巡检都会把快照 / 报告 / 页面**提交回本仓库**，
> 若加了 push 触发，那个提交会再触发一轮，接着又提交……**自己触发自己**。
> 所以「推完」不会「自动跑」，必须显式触发一次。

> **为什么脚本里带代理？** 这台机器直连 `github.com:443` 会被重置
> （反直觉的是 `api.github.com` 直连是通的），push 必须走本地 SOCKS5。
> 触发用的 PAT 从 git-credential-manager 读出，**只读、不落盘、不打印**。

退出码：`0` 通过 / `1` 推送或触发失败 / `2` 巡检本身失败。
