# 地市筛选口径更正 + 已下架条目的地市归属剔除（2026-09-24）

> 起因：用户报障「**联通邢台资费明明还有在售的套餐，我怎么看一个也没有，全都是停售状态**」。
> 结论：**页面没坏，数据也没丢 —— 是「按地市筛」的口径答错了问题**；顺着查出一处
> 「已下架条目的地市归属不可信」的真缺陷。两件事一起改，四网统一。

## 1. 复现与定性

页面（旧口径，联通 → 资费明细 → 地市选「邢台」）：**9 条，全部「已下架」**。
用户看到的字面含义是「邢台没有在售资费」——**与事实相反**。

拆开这 9 条：

| 来源 | 条数 | 说明 |
|---|---|---|
| 真·邢台专属 | 3 | 上游只有这 3 个邢台专属三级目录，且**全部归在「一级=99（停售套餐）」** |
| 各城「停售目录」差异带来的省版资费 | 6 | `全国流量王19元档-河北省版`、`联通5G智享套餐39元2026（河北）` … 被打上「9~11 城共有」标签 |

而邢台**实际能办**的在售资费 —— **4820 条** —— 全在「全省通用」那批里，被旧口径
（「只留 cty 含邢台的」）一句话排除掉了。

## 2. 根因：旧口径回答的不是「这个市能办什么」

```
旧：选某市 ⇒ 只留「上游目录里恰好写了这个市」的条目
新：选某市 ⇒ 「不限地市」的那批 ＋ 该市专属          ← 即「这个市能办什么」
```

对**四网全适用**：移动/电信的「无地市字段」、联通的「覆盖全部 12 城」同样都代表
不限地市，旧口径把它们一律排除。

## 3. 上游核对（不靠猜 —— 直接问接口）

`probes/probe_city_only.py --city 邢台`（44 个栏目组合 × 12 城，逐组合取三级目录并集）：

```
=== 只有 邢台 有的三级目录：3 个 ===
   一级 99(停售套餐)：3 个
   1元260G国内通用流量36个月（邢台）-立即生效
   1元1300分钟国内通用语音36个月（邢台）-立即生效
   1元220G国内通用流量36个月（邢台）-立即生效
邢台 独有 id 3 个；12 城全部 id 合计 9120 个
→ 该市的独有目录**全部**在「一级=99（停售套餐）」⇒ 上游确实没有该市的在售专属资费，
  按该市筛看到的在售条目来自「不限地市」那批。
```

证据落盘：`evidence/unicom-city-only-xt-20260924.{log,json}`。

## 4. 顺带查出的真缺陷：已下架条目的地市归属不可信

联通带城市归属的条目共 **139** 条，按在售/停售拆开：

| | 条数 | 单城 | 多城共有 |
|---|---|---|---|
| 在售 | 45 | 42 | 3 |
| **停售** | **94** | 79 | **15** |

停售那 94 条里，**6 条是「9~11 城共有」**，名称明写「-河北省版」「（河北）」——
它们本不该算「邢台专属」，却因为各城**停售目录的收录范围不一致**而进了邢台的桶。

> 🔴 停售目录本质是各城各自的**遗留清单**，同一条停售资费被哪些城市收录是**任意**的。
> `_cityNames` 直接继承了这个随机性 ⇒ 这个归属是噪声，不是「适用范围」。
>
> **更正一处我此前说错的数字**：先前口头给的「城市专属从 139 降到 121」是错的，实际是
> **139 → 45**（drop 掉的就是那 94 条停售）。

## 5. 改动（四层）

### 5.1 构建期（`cloud/tariff/tariff_monitor.py`）

新增 `CITY_NETS = {move, telecom, unicom}`（有条目级地市维度的网；广电只有全国/河北两档）。
`rows_of()` 里先算 `st`，再按**互斥且完备**的三态写盘：

| 形态 | 含义 |
|---|---|
| `cty: [...]` | 该资费限这几个市（中文名，取值域 = `CITY_ORDER ∪ CITY_EXTRA`） |
| `pw: 1` | **不限地市**（全省通用）—— 新增，页面「仅全省通用」档读它 |
| 两者皆无 | **归属不详**（当前只出现在**已下架**条目上） |

`pw` 的存在是必需的：已下架条目被摘掉 `cty` 之后，若仍靠「没有 cty = 全省通用」推断，
它们会**混进每一个地市档** —— 那正是要消灭的东西。构建日志相应改成成对打印
`地市专属 N · 不限地市 M`（只报一个数看不出另一批去哪了）。

### 5.2 页面（`cloud/tariff/template.html`）

- 选项改名：`全省通用（未限定地市）` → **`仅全省通用（不限地市）`**。
- `apply()`：`ct==="_none"` → `d.pw`；具体地市 → **`d.pw || cty 含该市`**。
- **「已下架」页签下地市维度整体失效**：控件禁用 + 取值清空 + 过滤当没筛
  （口径与既有保险丝一致：*无效筛选 = 不筛*，并把无效取值从控件与地址栏里抹掉）。
  不处理的话用户在这一页选某个市会得到 0 条，那会被读成「这个市没有下架资费」。
- `renderDims()`：选项条数改为「不限地市 ＋ 该市专属」且**只算在售**；
  累加时遍历**全部**城市档（某个市专属恰好为 0 时它仍是可筛档，不能当 0 条置灰）。
- 新增 `syncCtAvail()` —— 禁用态与提示文案的**唯一写处**，由 `apply()` 每轮调用
  （程序化设值不触发 `onchange`，只挂回调会静默不同步）。
- 副标题、总览「地市分布」、页脚「数据说明」同步新口径。

### 5.3 对账与探针

- `conformance.py`（独立 oracle）：`ct` 判据与页面逐字一致；档位条数按同一算法生成用例。
- `audit_data.py`：新增**互斥完备**三条判据（在售条目必须恰有 cty 或 pw 之一；无地市维度
  的网一条标记都不该有）；`fallback_miss` 排除已下架（否则电信天天误报）。
- `page_e2e_check.js`：地市断言从「结果必须收窄」改成**与数据精确对账**
  （见 §7 第 1 条）；新增「已下架页签下地市必须禁用且塞值不生效」。
- 新增 `probes/probe_city_only.py`（本次查案用的一次性脚本提升为可复用证据生成器，
  已登记进 README 证据表）。

### 5.4 CI（`.github/workflows/tariff-daily.yml`）

「校验页面归档」新增：`pw`/`cty` 互斥完备断言；广电侧加 `pw == 0` 反向断言；
`n_cty > 0 and n_pw > 0`（地市维度残缺即红）。

### 本轮踩到的三个坑（都已修，写在这里免得下次重踩）

1. **e2e 的旧判据「地市筛选必须让结果收窄」会把正确结果判成失败**。
   新口径下本网常常绝大部分都是不限地市（联通在售 4865 里 4820 条不限地市），
   选一个市**不收窄正是对的**。已改成与数据精确对账 —— 这比「收窄了」强得多：
   收窄只证明筛掉了点东西，证明不了筛对了。
2. **算档位条数时只遍历「cc 里已有的键」会误置灰**。某个市在售专属恰好为 0 时，
   cc 里根本没有这个键 ⇒ 置灰判据 `!cc[o.value]` 把这**能筛出整批不限地市**的
   档当成 0 条档置灰（实测「华北油田」就中招）。必须遍历**全部**城市档再累加。
3. **`run_conformance.py --html <相对路径>` 会拼出畸形的 `file:///` URL**，
   页面加载失败 → 所有用例报「页面缺控件 #x」。这一步是**失败**而非通过（没有静默），
   但报错方向容易被误读成「页面缺控件」。用绝对路径。

## 8. 遗留 / 待办

- 「不限地市」那批在**任意**地市档下都会计入 ⇒ 地市筛选对联通这类「以全省为主」的网
  **几乎不起收窄作用**。这是数据的真实形态，不是 bug；但如果将来要「只看这个市独有」，
  需要一个额外的档位（当前刻意不加，避免又一次「口径歧义」）。
- 已下架条目的归属现在**完全丢弃**（只在「全部城市」可见）。若哪天要恢复，
  必须先把「停售目录为什么各城不一致」问清楚，不能直接把 `_cityNames` 用回去。
- 浏览器类检查（walk / e2e / conformance）仍在 CI 之外，靠人跑 `run_checks.py`。
  接进 CI 是上一轮就记下的待办，仍未做。
