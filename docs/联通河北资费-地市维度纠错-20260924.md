# 河北联通资费「地市维度」纠错报告

- **日期**：2026-09-24
- **触发**：用户指出「联通河北资费每个市都有啊，还有个雄安，你重新探测」
- **结论**：用户正确。**旧结论「河北联通资费与 cityId 无关、只采一城」已证伪**。
  主链路因此**静默漏采 130 条资费**，已修正为「取 12 城并集」。
- **复现**：`python probes/probe_unicom_city_scope.py`（约 1 分钟，四层判据一次跑完）

---

## 1. 错在哪：一个典型的「抽样假阴性」

旧结论的判据是 `he_unicom_tariff.city_drift()`，它的取样是：

```python
combos = [("1", "1", "1001"), ("2", "2", "2004")]      # 套餐/移网、加装包/权益包
cities = [("石家庄","188"), ("邢台","185"), ("唐山","181")]
```

问题不在取样数量，而在**取样的位置**：这两个组合**恰好是全省一致的**。
真正随城市变化的组合（宽带、流量包、短信包、促销、停售套餐…）一个都没抽到。

于是得到「三城一致」的结论，写进代码注释与页面文案，主链路据此只采邢台一城。
**后果不是报错，而是静默漏数据** —— 日志、自检、页面全都看不出异常。

> 教训：判据的覆盖范围必须等于**被判定对象的取值范围**。
> 「抽查几个样本都一致」在样本选得不好时，结论可以完全反过来。

## 2. 四层判据（缺一即可能再次判错）

| # | 判据 | 本次结果 | 作用 |
|---|---|---|---|
| ① | 同城重复性：同参数连跑两遍 | 完全一致 | 排除「返回顺序抖动/分页截断」这个混淆项 |
| ② | 跨省区分度：河北 188 vs 北京 110 | 交集 **0**（77 vs 35） | 证明 provinceId/cityId 确实被服务端使用 |
| ③ | 差异语义：差异条目名 | 带「雄安 / 沧州 / 保定…」 | 证明差异是**城市专属资费**，不是排序差异 |
| ④ | 全组合覆盖：22 组合 × 12 地市 | 12 个组合存在差异 | 这一层就是当年漏掉的 |

补充判据 ⑤（决定采集成本）：

```
用邢台 cityId=185 去拉 2 个「仅雄安存在」的三级 id → 返回 2 条明细
⇒ operateData 按 id 解析，cityId 不设门槛
```

## 4. 采集策略（修正后）

```
① 菜单：对 12 个地市分别取 threeLevelName，按 (一级×二级) 求 id 并集
② 明细：按并集 id 拉 operateData —— 只需一遍（cityId 不设门槛）
③ 标注：每条记 _cities = 该资费出现在哪些地市（并集，非首次命中）
```

请求量对比：

| 方案 | 请求数 |
|---|---|
| 旧（单城） | 菜单 44 + 明细 ~450 ≈ **494** |
| 新（12 城并集） | 菜单 44×12 + 明细 509 ≈ **1037** |
| 若按「12 城各采一遍」 | ≈ 5900（**没必要**） |

实测一轮 1567 请求 / 58 秒（含判据 `city_scope()` 的 528 次）。
