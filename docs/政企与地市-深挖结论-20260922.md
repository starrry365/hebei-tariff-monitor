# 四网资费「政企 + 地市」深挖结论（2026-09-22）

> 目标：判断「政企资费」与「各地市资费」这两个维度，四网公开渠道**到底能不能拿到**。
> 方法：从各网前端 JS 挖出**完整接口清单**，再逐个实测（不猜路径）。
> 结论先行：**地市能拿到 2/4 网；政企 0/4 网（上游根本没这个数据）**。
> 落地决定：地市维度**只对移动 / 电信**出筛选（联通 / 广电隐藏该维度）；政企层**不做**。

---

## 一、地市级资费

### 1.1 可达性矩阵（读已归档快照统计）

| 网 | 条目级地市字段 | 12 地市命中 | 结论 |
|---|---|---|---|
| **移动** | `applicableArea` / `city` | **1974 次**（石家庄231 秦皇岛194 唐山188 沧州176 保定176 邯郸171 廊坊168 邢台166 承德150 张家口134 衡水116 省直辖104） | ✅ 有 |
| **电信** | `applicableArea`（`_areaCodes`） | **265 次**（邢台26 衡水26 沧州25 保定24 张家口24 承德24 石家庄21 秦皇岛21 省直辖21 唐山21 邯郸16 廊坊16） | ✅ 有 |
| 联通 | **无任何地域字段** | 0 | ❌ 无 |
| 广电 | 仅 `_areaNames`（全国/河北省） | 0 | ❌ 无 |

> 注：命中次数 > 条目数说明一条资费可覆盖多市（CSV），故实际"地市专属"条目数需按条目去重统计。
> 去重后（`probes/probe_city_matrix.py` 的口径）：**移动 481 条 / 电信 31 条**，均覆盖 12 市。

### 1.2 联通：为什么确定没有（4 条独立证据）

1. **12 城分类骨架逐条一致**：`indexData` 返回的 `(一级, 二级)` 签名在
   石家庄188/唐山181/秦皇岛182/邯郸186/邢台185/保定187/张家口184/承德189/沧州180/廊坊183/衡水720/雄安782
   **去重后仅 1 种**（6 个一级、22 个二级）。
2. **条目零地域字段**：`detailsList` 明细 24 个字段里没有任何 city / area 字段。
3. **发现但打不通的旁路**：JS 里另有一族 `/queryTariff/*`（`countryTariffQuery`、
   `TariffMenuDataThreeHomePage`、`tariffDetailInfo`…），`baseUrl` 经反混淆确认为
   `https://mxx.client.10010.com/servicequerybusiness`。
   **实测 5 种调用方式（GET / POST-form / POST-json / 换 `provinceCode` / 全参数）全部 9s 超时**，
   而同一时刻老端点 `queryTariffNew/threeLevelName` **0.1s 正常返回** ⇒ 该族在**河北侧不被路由**。
4. **其他 service 域**：`servicebusiness` / `servicetransactbusiness` / `serviceimportantbusiness`
   下的端点实测 404 或返回无关内容（`getTariffspecification` 返回的是**长途直拨资费标准规格表**，
   不是资费清单）。

⇒ 联通 **不是"没找到"，是上游没有**。

### 1.3 广电：为什么确定没有

`busi/qryAreaList` 全量返回 **33 个区域，全部是省/直辖市粒度**
（HB00 河北 / HB01 湖北 / HLJ0 黑龙江 / NMG0 内蒙古…，只有 GZ00 广州、SZ00 深圳两个城市特例）。
`applicableArea` 传地市码（`HB0001`/`HB1305`/`HB130500`）一律回
**`BASE102 区域编码无效`** ⇒ **上游区域码表里就没有河北地市**。

> ⚠️ 别按 `HB` 前缀判省 —— `H` 开头的两字母码不只河北（`HB01` 就不是），要按区域表的 `areaName` 判。

### 1.4 移动：地市只能靠条目字段，无独立入口

`getType2List` / `getTariffListInfo` 的 `province` 参数传地市码
（3100/3110/3120/3130/3150/3160/3170/3180/3190/3350）→ **分类列表 `n=0`**，
接口不存在"按地市查"的能力。地市维度**只能**用条目自带的 `applicableArea` 筛。

## 二、政企资费

### 2.1 公开接口层：四网全部没有

| 网 | 政企入口 | 实测结果 |
|---|---|---|
| 移动 | `isPublic="0"` | `getType2List` 能列出 **25 组**分类（比在售 18 组还多），但 `getTariffListInfo` **每组 `total` 恒为 0**、`series=0`。`linkScn` 1/2/3 全试一致。猜测的旁路 path 全回 `40401 service not exist` |
| 联通 | 一级分类只有 1..5 + 99（停售），**无政企类** | 旁路见 1.2 第 3/4 条 |
| 电信 | 分类树 5 个一级（套餐/加装包/营销活动/国际港澳台/标准资费），**无政企** | 加密层已完全打通，接口 familyCode 只有 `tariffSectionHome` / `tariffSectionQuery` |
| 广电 | 分类树里有 `ZQ 政企` 节点，但 **`childTariffTypes` 长度 = 0（空壳）**；且 `type1` 参数被服务端**完全忽略**（传 GZ/ZQ/1/2 都返回同样 131 条） | 无 |

### 2.3 唯一可用的政企信号：`applicablePeople`（目标客户）文本

| 网 | 纯政企 | 两者均可 | 纯个人/公众 | **未标注** |
|---|---|---|---|---|
| 移动 | 2 | 0 | 52 | **3833（98.6%）** |
| 联通 | 18 | 4 | 315 | **7562（95.7%）** |
| 广电 | 0 | 0 | 8 | **316（97.5%）** |
| 电信 | 0 | 44 | 94 | **746（84.4%）** |

典型原文：
- 电信：`河北公众客户/政企客户均可办理。`（44 条）
- 联通：`全网政企用户`、`全网用户，需所属单位开通联通5G随行专网…请咨询相应政企客户经理`
- 移动：`限合作政企成员且新入网的10元放心享套餐用户办理`

⇒ **84%~99% 的条目根本没写客户类型**。想靠文本分档撑起「个人/政企」两大层，**政企档只有 68 条**
（移动2 / 联通22 / 电信44 / 广电0）—— 这就是**不做政企层**的直接原因。

## 三、结论与唯一剩余的突破口

1. **地市**：移动 ✅、电信 ✅、联通 ❌、广电 ❌。后两网是**上游没有**，非采集问题。
   ⇒ 页面**只对移动/电信**出地市筛选；联通/广电**隐藏**该维度（不是置灰 —— 置灰会诱使用户
   以为"本网暂时没有地市资费"，隐藏才是诚实的表达）。
2. **政企**：四网公开渠道**都没有**独立政企资费清单；能拿到的只有"目标客户"文本提到的 68 条。
   ⇒ **本次不做政企层**（用户决定）。
3. **唯一可能突破的路径**：**真机 App 抓包**。
   - 各网 App 内有原生"政企专区"入口，走**原生接口**（非 H5），前面挖的是 H5 层。
   - 但前提是**持有政企账号**；且拿到的会是"本企业可办业务"，仍非全量政企资费清单。
   - 需要：手机 + Fiddler 代理（本仓库已有 8866 代理重建版）+ 安装证书。

## 附：证据生成器（已入库，`probes/`）

本次所有结论都配了**可复跑的探针**，不用回头再挖一遍：

| 探针 | 用途 | 证明什么 |
|---|---|---|
| `probes/probe_city_matrix.py` | 读快照统计四网地市码 | 移动 481 条 / 电信 31 条（各 12 市）；联通 / 广电 **0 条** |
| `probes/probe_upstream_limits.py uni` | **实时**打联通接口 | 旁路 `/queryTariff/*` 5/5 条 8s 超时，**同刻老接口 207ms 正常**；12 城骨架签名 **1 种** |
| `probes/probe_upstream_limits.py cbn` | **实时**打广电接口 | 区域表 33 个全是省级；地市码回 **BASE102**；`ZQ` 节点 `children=0`；`type1` 被忽略 |
| `probes/probe_zq_text.py` | 读快照统计 `applicablePeople` | 政企相关占比 0.1% / 0.3% / 0.0% / 5.0%，**未标注 84%~99%** |

同一条结论也**钉进了 CI**（`.github/workflows/tariff-daily.yml` 的「校验页面归档」步骤）：
联通/广电一旦出现带地市码的条目、或移动出现下架数据、或地域标超出 `{hb,cn}`，
CI 会**直接失败**并提示「上游语义已变，需人工确认」—— 结论漂移不会静默。

**方法论要点**：本次所有"没有"的结论，都用**同一通道的对照组**验证过
（"新接口族超时"必须同时验证"老接口正常"；"广电没有地市"必须同时验证"HB00 能取到数"），
避免把限流 / 网络抖动 / 凭证失效误判成"上游没有"。
