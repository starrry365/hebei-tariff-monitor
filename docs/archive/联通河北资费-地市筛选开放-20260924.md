## 2. 三个关键设计决策

### 2.1 地市命名空间统一成**中文名**，而不是任何一套码

移动/电信的条目级地市码是 **4 位**（3190=邢台），联通的是 **3 位**（185=邢台）。
两套码并存时，页面拿到一个 `cty` 值得先问「这是哪张表的」—— 而值本身长得也像（纯数字），
判错的结果是「某个市的筛选恒为空」，不报错、看着像「这个市本来就没资费」。
统一成中文名后只有一套，且与下拉里显示的文本逐字相同。

### 2.2 用**数据**决定维度显隐，废掉 `allProvince` 声明

`allProvince` 是数据源自报「本网数据不分城市」。它的致命之处不是写错，而是
**写错时不会有任何报警**：页面信声明、不信数据，于是一个错的声明就把整个维度藏掉了。
联通那次正是如此。现在页面按「本网有没有任意一条 `d.cty`」自己判 ——
数据里没有地市信息时宁可不给这个维度，也不拿一个不存在的维度去筛。

### 2.3 判据只留**一份权威**（在构建期）

地市判据（`WHERE_OF` + `text_cities`）只在 `tariff_monitor` 里算，写进行数据 `d.cty`；
页面与对账脚本都**只读结果**。此前页面与 `audit_data` 各有一份文本规则、靠 `check_sync`
比对字符串 —— 那份副本**已经漂过一次**（页面升级成「地市码优先」而脚本没跟上，
37 个用例恒失败却没人发现，因为平时没人跑）。现在 `check_sync` 改查
「那份唯一的权威有没有被完整地送到页面」。

## 4. 顺带查出的问题（这才是本轮最值钱的部分）

把 `--net unicom` 加进体检后，它**第一次**被这套判据扫过（此前 CI 只跑 move / telecom），
一次性暴露 5 处。逐个定性：

### 4.1 【真 bug】联通的 `du='M'` / `'T'` 认不出，流量筛选**静默漏条目**

`市场-1元100M流量包` 的 `d=100, du='M'`；`群组账户专属1T国内通用流量` 的 `d=1, du='T'`。
构建期 `gb()` 只认 `GB/MB/TB` 前缀 ⇒ 这 4 条算出 `g=None` ⇒ 在「流量」列显示「—」、
在「每元流量」排序里**凭空消失**，看起来像「上游没填流量」。

**修**：新增构建期 `du_norm()`：
- 单位别名归一：`M`/`M/B`→`MB`、`G`/`GB起`→`GB`、`T`→`TB`
- 数值为 0 ⇒ 归一成「无流量」（`d='' du=''`）
- **认不出的单位原样保留**，交给体检的白名单报出来（上游新增单位必须人工过目，不能默默吞）

🔴 归一只动「单位认不出」或「数值为 0」的行，**绝不碰正常数据**：
`d='0' du='GB'`（四网合计 9556 条）是上游表达「本套餐不含流量」的标准写法，
`gb()` 算得 0.0、页面显示「—」、体检本来就过 —— 归一它属于无事生非。

**A/B 证据**（把 `du_norm`/`fee_norm` 还原成恒等函数再跑一遍 `rows_of`，逐行比对）：

| 网 | 变动行 | `g` 语义变化 |
|---|---|---|
| move | **0** | 0 |
| cbn | **0** | 0 |
| telecom | **0** | 0 |
| unicom | 209（`d`/`du`/`f` 显示值） | **4**（正是那 100M/200M/500M/1T） |

### 4.2 【判据过严】广电 9 条空上架/下线日被当成「格式错」

页面**本来就有**「无上架日期」这一档（`<option value="none">`，筛选写成
`if(on==="none"){if(dt)return false}`）—— 空日期是**一等公民**，不是错误。
真正危险的是「非空但页面解析不出」的值（如 `2026/09/24`）：`toDate()` 返回 null，
那条悄悄落进「无上架日期」桶里，无人察觉。

**修**：`audit_data.check_fields` 改为「空，或 8 位真实日历日」才算合法，并单独打印空值条数。

### 4.3 【检查自己坏了①】`page_e2e_check.js` 的地市样本取错，假失败

它原本取「第一个**可点且非 `_none`** 的地市档」当样本 —— 联通第一个可点档是**石家庄**，
而石家庄 19 条**全是已下架**，在默认的「在售」页签下筛出 0 条 ⇒ 报
`地市 石家庄 筛出 0 条`，看着像地市筛选坏了。

**修**：逐个试、取**在当前页签下真有条目**的那个（联通会自动跳到唐山 7 条）。
一个都没有才判失败 —— 那才是真筛不动。

### 4.4 【检查自己坏了②】`page_conformance_check.js` 与 oracle 的页签口径不一致

消费者脚本把 `STA` 固定成 `"0"`（在售），而 oracle 是对**全量 rows** 求值的。
此前恰好等价 —— 因为 move / telecom 的「已下架」恒 0 条（在售 ≡ 全部），**差异被数据掩盖**。
联通有 3177 条下架，于是 oracle 期望 7903 而页面量到 4820，**26 个用例集体对不上**。

**修**：`STA=""`（页面 `apply()` 里 `if(STA!==""&&...)` 才过滤状态，`""` 即「全部」），
恢复原注释就写明的本意「让页面显示全部行以对齐 oracle」。

### 4.5 【检查自己坏了③】`probe_upstream_limits.py` 的判据**天生看不见差异**

这是**上一轮假阴性的源头**：它比的是 `indexData` 的**两级骨架**
（`firstLevel:secondLevels`），而真正随城市变的是**三级目录 id**（住在另一个接口
`threeLevelName` 里）⇒ 两级骨架天生对差异视而不见，于是得出「换 cityId 不影响数据」。

**修**：B 段拆成 B1（旧判据，**留证**，并写明它为什么看不见）+ B2（现行判据，直接调
采集器的权威 `city_scope()`，不再另写一套）。`probe_city_matrix.py` 同步更正期望值
（联通 ❌ → ✅）并让它**同时认**两种来源：字段里的 4 位码（移动/电信）+ 采集侧
`_cityNames`（联通）。

### 4.6 顺手更正一处数字矛盾

「22 个 (一级×二级) 组合里有几个随城市变化」在代码注释里写 **8**、在报告里写 **12**。
跑权威判据 `city_scope()` 定论：**12 个**（单城 8991 → 并集 9121，净增 130）。
5 处「8 个」已全部更正为 12，并把「沧州 41 / 57」两个数的口径标注清楚
（41 = 专属**三级目录**数，57 = 专属**资费条数**）。

### 4.7 【CI 缺口】裸 `git push` 遇到并发推送就丢数据（验证 CI 时实测踩到）

按要求实跑 `workflow_dispatch` 校验时，本机**同时也推了一次**（提交 `378db33`）。
结果这轮 CI：**除最后一步外全部 success**，唯一失败的是「提交数据与归档」：

```
[main 95cf91f] data(tariff): 资费巡检 2026-09-24
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/starrry365/hebei-tariff-monitor'
```

裸 `git push` 只在「远端没动过」时才成功。**偏偏失败的是「把数据留下」那一步** ——
前面 13 个检查步全绿，数据却随 runner 一起销毁。触发条件很日常：本机手动推过、
或两轮 CI 重叠（定时 + dispatch / 重试）。

**修**：commit 后 push 被拒 ⇒ `git pull --rebase -X theirs` 重试，最多 3 次；
三次仍失败才让本步失败（在 Actions 上看得见）。

⚠️ 冲突一律取**本轮**（数据是刚采的）：**rebase 里 `ours`=远端、`theirs`=本地**，
与 merge 相反 —— 写反就变成「远端旧数据覆盖本轮新数据」，而且**不会报错**。

本地模拟三种冲突形态验证（临时 bare 仓库 + 两个 clone 制造竞态）：

| 形态 | 结果 |
|---|---|
| 改动不重叠（真实场景：本轮改 `snapshots/`，手动推改 `README`） | 第 2 次 push 成功，两边内容都在 |
| 同一**文本**文件双方都改（`state.json`） | 第 2 次成功，落盘 = **本轮**版本 |
| 同一**二进制**文件双方都改（`snapshots/*.json.gz`） | 第 2 次成功，落盘 = **本轮**版本 |

三种形态均**无 rebase 残留**。改完再触发一次 `workflow_dispatch`（全程不推）复核。

## 5. 遗留

- **公开 Pages 站与 `page/index.html.gz`**：入库的那份归档是「与本仓库快照同源」的，
  现在还是旧采集器产物（联通 7912 条、无地市层）。**本轮刻意不动它** ——
  本机预览路径一律走 `archive=False`，不覆盖归档。下一次 06:00 CI 跑完，
  快照 / 归档 / 线上页面会一起更新（联通条数会从 7912 跳到 8042 = **+130**，
  正是「单城静默漏掉」的那批，届时变更报告会如实标出来）。
- **`probe_city_matrix.py` 对 09-24 及更早的联通快照会报「！变」**：那是旧采集器
  的单城产物（条目上没有 `_cityNames`），不是上游变了 —— 探针里已加了这个提示。
- 广电 324 条仍是唯一没有地市维度的网；页面按「有没有 `d.cty`」自动不出这一层。

### 📌 后记（同日，晚）

本文交付的「地市维度开放」在**当天即被用户报障推翻了一半**：口径写成了「选某市 ⇒ 只留
`cty` 含该市的」，而那是「上游目录里恰好写了这个市」，不是「这个市能办什么」——
用户按邢台筛得到 9 条全停售（而邢台能办的 4820 条全在「全省通用」里被排除），
读起来就是「邢台没有在售资费」。

已更正为「**选某市 = 不限地市 + 该市专属**」，并把**已下架条目的地市归属整体剔除**
（那批归属来自各城停售目录的差异、收录范围任意）。同时新增 `pw`（不限地市）标记、
「已下架」页签下地市维度禁用。**本文 §1 表格里对页面口径的描述与 §2 的部分结论
已被新版取代** —— 以 `docs/联通河北资费-地市口径与已下架归属-20260924.md` 为准。
