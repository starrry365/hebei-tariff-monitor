# 联通筛选系统重做 —— 2026-09-24

## 为什么重做

对联通在**旧筛选口径**下的实际表现做了量化，三处硬伤全部来自数据实证：

| 维度 | 旧现状 | 实证 |
|---|---|---|
| 类型 / 细分 | 两个下拉对联通**完全重复** | `ty` 就是一级栏目名（6 个值），`cat` 是它的 1:1 映射 ⇒ 选了大类，细分只剩 1~2 项 |
| 板块（全国资费 / 本省资费） | **页面上根本没有入口** | `a1` 字段在行数据里躺着：全国 6205 / 本省 1836 |
| 「停售套餐」把分类吃掉了 | **3177 条归类错误** | 一级写「停售套餐」时，真实分类其实在二级栏目里 —— 其中 1220 是加装包、581 是标准资费、303 是营销活动、42 是港澳台国际，却被一律归成 `cat=套餐` |
| 二级栏目 | **完全没进数据** | 上游 22 个二级栏目（移网/宽带/融合/流量包/权益包/新业务/促销/合约…）一条都没落到行数据 |

四网对照后确认：**「类型 / 细分重复」在移动、联通、电信三网上都存在，只有广电是真两级**。
联通最有信息量的两个维度（板块、二级栏目）一个没有、一个被吃掉，而现成的两个维度是重复的。

## 改了什么

### 构建期口径（`tariff_monitor.rows_of`）

- **联通「停售套餐(99)」按二级栏目还原成真实分类**：一级写「停售套餐」时，`cat` 改取二级栏目
  经 `type_cat` 归一后的值（3177 条停售 → 加装包 / 标准资费 / 营销活动 / 港澳台国际…）；
  「停售」这个状态改由**「已下架」页签**表达，不再占用分类维度。
- **`ty`（细分）改为上游二级栏目**（仅联通；其余三网上游没有二级栏目，保持原一级分类）。
- **新增 `sect`（板块）**：上游 `tariffAttr` → `全国资费` / `本省资费`，**仅在本网该字段真有两档时落盘**
  （移动 / 联通 / 广电有两档；电信上游只有一档 ⇒ 不落盘，页面上这一格整个不出现）。
- 溯源字段 `l1` / `l2`：仅当归一结果与原文不同时写入，供排查。

效果（联通 8042 条）：`套餐 954 · 加装包 3454 · 营销活动 729 · 标准资费 2481 · 港澳台/国际 424`
—— 原「套餐」里被误吞的 3177 条停售各归其位。

### 页面筛选模型（`template.html`）

- **新增「板块」维度 `#sb`**：`DIMS` / `DIM_PRE` / 深链 / CSV / 清空复位全链打通；
  本网只有一档时**整格（含标签）隐藏**。
- **三级联动：板块 → 类型 → 细分**，档位条数随上级条件刷新。
- **筛选谓词抽成唯一函数 `match(d,c)`**：`apply()` 筛结果与「每个档位几条」（`syncDims`）
  **共用同一份判据** —— 此前是两份副本，改一处忘另一处 = 「选项写着 8 条、点进去 5 条」。
- **保险丝统一收口到 `condOf().dimOff`**：本网不存在（隐藏）或已置灰的维度一律「不筛」，
  不再拿一个不存在的取值筛出「0 条」的假答案（地市 / 归属 / 板块三条同一口径）。

### 界面

- 筛选栏按语义分区：**范围（板块/地域/地市）· 分类（类型/细分）· 资费（月费/流量/通话/宽带）·
  办理（渠道/归属）· 时效（上架/下线/变更）· 排列（排序/方向）**。
  每区一个玻璃小面板、左侧组标签；「排序 / 方向」单列成「排列」区 —— 它们**不是筛选条件**，
  混在筛选格里会让人以为它们也参与过滤。
- 本网没有的维度**连标签整格隐藏**（旧版只藏 select，剩一个悬空的「归属」字样）。
- 全部控件 `id` 一个没改 —— 深链（`#cat=…`）、CSV、判据、探针全按 id 取值。

### 判据与自检

- 新增 `probes/probe_filter_dims.py`（进 `run_checks` 第 2f 项、CI 第 18 步），三条判据：
  1. 联通停售行里 `cat != 套餐` 的必须占多数（只查「cat 越界 = 0」会被「全改成套餐」骗过去）；
  2. `ty` 取值域 ⊆ 上游真实栏目（不许凭空造词；域为空也算废了）；
  3. `sect` 只在本网 `tariffAttr` 真有两档时落盘。
  **阴性对照**：把页面里「本省资费」改成「全国资费」⇒ 三网齐报「只有 1 个板块档却落了盘」。
- `conformance.py` 的 oracle 补上 `cat` 维度；两条「套餐」用例从 `ty` 改走 `cat`
  （联通细分域修正后已无「套餐」这一档，写 `ty=套餐` 会让用例在页面上「无此取值」被跳过 ——
  **跳过 ≠ 通过**）。

## 过程中抓到的一个真 BUG（值得记住）

`syncDims` 最初把「组合恰好 0 条」的档也**清值**，等于静默摘掉用户已选的条件：

> 先选「细分＝加装包」，再选「宽带＝含宽带」→ 本该诚实给 0 条，
> 页面却给出 85 条（宽带的全部），筛选标签上的「细分：加装包」同时消失。

一致性对账抓到（四网 20+ 例，全部「期望 0、实际 85/74/…」）。
修法：**全页只保留一处「联动清值」** —— 细分项不属于当前所选大类时（`data-cat` 从属关系）；
「组合恰好 0 条」必须诚实显示 0 条。

## 遗留 / 刻意没做

- 电信上游只有一档板块 ⇒ 页面上没有「板块」格 —— 这是**按数据判**的正确行为，上游补了两档会自动出现。
- 广电上游没有条目级地市 ⇒ 「地市」格在广电不出现（同上，原有行为）。
- 「细分」档位数多的网（联通 14 档）下拉较长，未做分组 optgroup —— 等真有人反馈再做。
