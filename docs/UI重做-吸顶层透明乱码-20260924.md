# UI 重做 —— 吸顶层透明导致滚动内容穿透叠字

> 2026-09-24 · 触发：用户发来截图「你看看这个界面有问题吗」（红箭头指着顶部那个 `0 元`）
> 后续指令：「还是不行，重新UI，保留所有功能」

---

## 0. 一句话结论

用户圈的不是数据，是**渲染**：吸顶的「视图页签条」**没有背景**，
往下滚动后表格行从它下面透上来，和「数据总览 / 资费明细 / 变化历史 / 数据说明」
叠成了一坨乱码（那条 `0 元 — 数据总览 全国 通话尊享服… 资费明细 个人 — 变化历史 20 数据说明`
其实是**一行表格数据**与**四个页签名**的重影）。

根因不是「漏了一个 CSS 值」，而是**吸顶层被拆成了三层各自定位的元素** ——
任何一层忘了不透明、或 `top` 算错一点，就会重现。所以这次不是补背景，而是
**把吸顶层合成一个盒子（`#deck`），并重做整页 UI**；功能与全部 id / 深链契约原样保留。

---

## 1. 从截图到根因（四步）

### ① 先把截图读清楚

放大原图（1920×869）后确认：顶部那条里混着**两类文本**——
`数据总览 / 资费明细 / 变化历史 / 数据说明`（页签名）
和 `0 元 / — / 个人 / 20 / 2028-12-31 / 6 天后生效 待上架 / 829 天后到期`（表格单元格值）。
红箭头指的 `0 元` 是**最左边那个透出来的单元格值**。

而且页面**没有**顶栏（"河北移动 · 资费全量目录"那块）⇒ 页面是**滚动过的**。

### ② 在真实 Chrome 里复现（1920×869，与截图同尺寸）

把与线上同源的 `cloud/tariff/page/index.html.gz` 解压后加载，切到「资费明细」、
滚到与截图相同的位置 —— **一模一样的乱码**（`20 元 — 数据总览 河北 2026移动房… 资费明细 …`）。

同时用 JS 取到第一行的文本：

```
["0 元——全国通话尊享服务加装包个人—适用省份用户2026-09-306 天后生效 待上架2028-12-31829 天后到期"]
```

—— 与截图那条乱码里的 `0 元 / 全国 通话尊享服… / 个人 / …6 天后生效（待上架）/ 2028-12-31 / 829 天后到期`
**逐项对得上**。⇒ 「透上来的那一行」= 表格第 1 行，确认无疑。

### ③ 量三层吸顶元素

```
scrollY=420
  #vtab  top=0   h=46   background = rgba(0, 0, 0, 0)   ← ★ 全透明
  .bar   top=46  h=230  background = rgba(255,255,255,.66) + blur(18px)  ← 有面，所以看得清
  thead th top=276                                          ← 位置本来就是对的
```

`.bar` 有 `glass` 类、`#vtab` **没有** —— 一行之差。`.bar` 那层因为有不透明 + 模糊，
把下面的行糊掉了；页签条什么都没画，于是那行原样透上来。

### ④ 为什么这条会漏到线上

因为它**只发生在滚动之后**，而且：
* `rect.top` 完全正常 —— 透明不影响几何；
* `elementFromPoint` 完全正常 —— 命中测试返回最上层元素，与透明度无关；
* 事件绑定正常、可点性正常、未捕获异常 0、连跑逐字节一致。

**既有 14 项检查没有一项能表达「这块面是不是透的」** —— 唯一能量它的量是**背景色的 alpha**。

## 2. 根因（结构性的，不是一次性手误）

```
旧结构：三层各自 position:sticky，靠 top 递增 + z-index 排序
   .nav    position:relative  z=40      （不吸顶）
   #vtab   position:sticky top=0     z=39   ← 忘了背景
   .bar    position:sticky top=--vtabh z=38
   th      position:sticky top=--stackh z=5
```

「吸顶层必须有背景」「top 必须递增」这两条在旧结构里都是**需要人去记住的约定**：
CSV 排序的 12 维控件、换网、窄窗口换行都会让层高变化，`--vtabh` 靠 JS 实量写入；
约定一旦漏掉就出事，而且**出事时静态看代码/看 rect 都看不出来**。
上一次同类事故（2026-09-23）就是「三层都写 top:0 ⇒ 页签和整条筛选栏被顶栏盖住」。

```
新结构：一个吸顶盒子
   #deck   position:sticky top=0     z=39    background = var(--card)   ← 实色
     └ #vtab   （普通流，不定位）                ← 自己不用管背景
     └ #bar    （普通流，不定位）
   th      position:sticky top=--stackh  background = var(--card2)      ← 实色
```

合成一个盒子之后，「吸顶层有实色背景」不再靠约定 —— `#vtab` 与 `#bar` 都在
盒子的实色面里，**写不出透**这个错。

## 3. 顺手做掉的另外几个隐患

| # | 隐患 | 处理 |
|---|---|---|
| 1 | `.bar` 的 `rgba(255,255,255,.66)` + blur 是**半透明**，严格说也在透（只是被糊掉） | 吸顶层改用**实色** `--card` |
| 2 | `th` 用 `--glass3`（α=0.94）+ blur，表头压在滚动行上，6% 也在透 | 改实色 `--card2`，并顺手去掉表头上的 `backdrop-filter`（5000 行滚动时的性能负担） |
| 3 | **筛选控件没有标签**：13 个下拉挤一行，默认项文字（「全部月费」「不限流量」）既是标签又是取值，改完值就认不出哪格是哪格 | 每个控件上方加小标签，改网格布局 |
| 4 | 表格整体 `backdrop-filter` 覆盖 5000px 高的元素 | 改实色卡面（`--card`），省一层合成 |

## 4. UI 重做做了什么

### 结构
* `#vtab` + `#bar` 包进**唯一吸顶盒子** `#deck`（`position:sticky; top:0`）。
* `#bar` 从 `<section id="v-list">` 里**上移到吸顶层**（必须与 `#vtab` 同盒）。
  它只在「资费明细」页有意义 ⇒ 显隐改由 `body[data-view="list"]` 驱动，
  `setView()` 里同步写 `body.dataset.view`（唯一视图入口，不会漏路径）。
* `--stackh`（表头粘性偏移）改**直接量 `#deck`**，不再「页签高 + 工具条高」两数相加
  （相加等于视觉下沿是隐含前提；直接量盒子则不需要这个前提）。

### 视觉
* 顶栏：品牌 + KPI 药丸（在架/已下架/本次变更）+ 主题按钮，四网切换独立一行。
* 吸顶层：底部圆角的实色卡片，顶部一条主题色渐变细线（吸顶时上沿严丝合缝贴住视口顶，
  所以圆角只给下面两角）。
* 工具条三行：① 状态页签 ＋ 搜索 ＋ 重置/导出 CSV/保存本页（**操作按钮终于和搜索同排**）
  ② 15 个带小标签的维度网格（`auto-fit minmax(122px,1fr)`）③ 快捷 chips。
* 表格：实色卡面、吸顶表头、斑马行 + hover、数值列等宽数字（`tabular-nums`）。
* 保留深浅双主题与四网主题色（`data-theme` × `data-net`）。

### 保留的全部契约（自检脚本依赖，一个没动）
* **id**：`vtab` / `v-{ov,list,hist,about}` / `bar` / `tabs` / `kw` / `sc` / `ow` / `cat` / `ty` /
  `ct` / `pf` / `gf` / `cf` / `bw` / `chx` / `on` / `off` / `chg` / `sort` / `dir` /
  `reset` / `csv` / `offline` / `chips` / `chipchg` / `stat` / `tb` / `prev` / `next` / `pg` /
  `themeBtn` / `ovStats` / `histBox` / `histTog` / `netnav` / `notice` / `navCnt` / `navStop` /
  `navChg` / `updTxt` / `sub` / `h1` / `logo`
* **类**：`.tab(.on)` / `.view(.on)` / `.chips button[data-p]` / `.fchip` / `.stat` / `.bfill` /
  `.tnode` / `.tnet` / `.tcap` / `.cpbtn` / `.pager` / `.thd` / `.ar` / `th[data-k]` / `.bg-*`
* **功能**：四网切换、3 状态页签、15 个维度筛选、类型两级联动、地市档位置灰/禁用、
  快捷 chips（互斥 + 可摘）、排序（10 列 + 方向）、分页、行展开详情、复制、
  导出 CSV、保存本页、深浅主题（localStorage）、深链（`#v=`/`#st=`/`#sc=`/`#cty=`…）、
  变化历史时间线、数据说明。

## 6. 新增判据（含阴性对照）

**为什么要有两条**：静态那条进 CI（快、每次跑）；浏览器那条在本机跑，
量的是**真实 computed style**（能抓到内联样式、JS 动态改样式、主题变量覆盖）。

```
$ python probes/probe_sticky_layers.py
  OK   .deck     background: var(--card)
  OK   th        background: var(--card2)
  吸顶规则 2 条（合格 2 / 不合格 0）
  ✅ 通过：2 条吸顶规则全部自带实色背景，且存在唯一吸顶根 #deck

# 阴性对照：把 .deck 的背景换成半透明 var(--glass)
  ❌ 吸顶层 '.deck' 的背景不是实色（var(--glass)）⇒ 滚动时内容会从它下面透上来与它叠成乱码
  结论：失败（1 个问题）        → exit=2 ✅ 判据有效
```

**反空转**（吃过亏的地方）：一条吸顶规则都没匹配到 ⇒ **判失败**，不把「没找到」当「通过」。

浏览器侧实测（深色主题、滚动 600）：

```json
{"scrollY":600,
 "vtab":{"top":0,"h":52}, "bar":{"top":52,"h":230}, "th":{"top":283,"h":43},
 "stackh":"283px",
 "stickyRoots":["#deck bg=rgb(13, 33, 56)", "th bg=rgb(19, 44, 72)", "…×10"]}
```

吸顶根只有 `#deck` 与 `th`，**背景全是不透明 rgb**（无 alpha 通道）。

## 9. 遗留

1. **吸顶层高 283px**（页签 52 + 工具条 230），在 869px 高的窗口里占约 1/3。
   这是**验收判据决定的**：`page_walk_check.js` 要求滚动后 `#bar` 紧贴 `#vtab` 下沿、
   且 13 个维度下拉全部可见可点（做成折叠会让多数组件变 `HIDDEN`，等于自我阉割覆盖）。
   如果确实想瘦身，得**同时改判据**，属于另一件事，需要单独确认。
2. 浏览器类检查（walk / e2e / conformance / `opaqueOk`）**仍只在本地跑**，未进 CI；
   CI 里只有静态那条 `probe_sticky_layers.py` 能覆盖这一类。
3. 本页仍是**表格形态**（早先用户明确选择「保留表格形态，只做美化」）；
   若想改成卡片流/双栏详情，是另一种信息架构，需另行确认。
