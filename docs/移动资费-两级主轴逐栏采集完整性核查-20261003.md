## 一、先问对问题：官网上「一栏」是谁决定的

这是本次核查最关键的一步。**如果栏目清单是官网硬编码的，而本站只信任接口，
那接口少声明一栏就会静默漏采**；反之如果官网自己也读接口，两者就不可能不一致。

### 1.1 两级轴：硬编码

官网主 bundle（`.tools/tariff/index.js.raw`，sha256 `9e0cc488…79ba3`）中：

```js
'yjfl':       '1',
'yjflList':   [{'label':'个人资费公示','value':'1'}, {'label':'政企资费公示','value':'2'}],
'rangeType':  '1',
'rangeTypeList':[{'label':'全网资费','value':'1'}, {'label':'分省资费','value':'2'}],
'zflx':       '',
'zflxList':   [],     // ★ 空
'zflxListAll':[],     // ★ 空
```

- **归属轴**（`yjfl`，个人/政企）＝ 硬编码 2 项 → 本站 `type1` 1/2
- **范围轴**（`rangeType`，全网/分省）＝ 硬编码 2 项 → 本站 `tariffAttr` 1/2
- ⚠️ 官网原文是「**分省资费**」，本站显示为「河北资费」（面向河北用户的本地化叫法）。
  仅显示层差异，见 `SB_LABEL`。

### 1.2 类目栏：动态，且来源就是 `getType2List`

`zflxList` 在初始化时是**空数组**，靠 `getZFLXListAll()` 填：

```js
// getZFLXListAll()
body = {'province': selectProv.code, 'isPublic': this.isPreview ? '2' : '1'};
rsp  = getZFLXListRequest(body);                       // → 打 getType2List
rows = setTariffAttrAndFilter(rsp.rspBody.data, ['tariffAttr','type1','type2']);
this.zflxListAll = rows;
this.setZFLXList();

// setZFLXList()
zflxList = zflxListAll
  .filter(x => x.type1 == this.yjfl && x.tariffAttr == this.rangeType)  // ★ 按两级轴过滤
  .map(x => ZFLXMAP.find(m => m.value === x.type2))
  .filter(Boolean)
  .sort(按 value 数字升序);
if (zflxList.length === 0) { showUnder = false; setPageState('SPECIAL_EMPTY'); }  // 空 → 空状态
```

而 `getZFLXList` 的实现（bundle 中 `_0x532317['getZFLXList'] = _0x4adc33`）：

```js
url = host_wx + 'nrapigate/nrtariff/new/Tariff/getType2List'
```

**⇒ 官网的栏目清单 = `getType2List` 按 `(type1, tariffAttr)` 过滤后的结果。**

本站采集侧（`tariff_monitor.py`）：

```python
T.call("nrtariff/new/Tariff/getType2List", {"province": T.PROV, "isPublic": "1"})
```

**同一接口、同一网关、同一参数**（`province=311`、`isPublic=1`）。
两者读的是同一份声明，栏目清单不可能不一致 —— 所谓「接口少声明一栏」，等于
「官网自己也少一栏」。**这不是漏采，这是官网确实没有这一栏。**

## 三、三处「看着像缺一栏」的地方

这三处最容易引发误解，逐条解释：

| 现象 | 真实原因 |
|---|---|
| **全网资费·个人没有「标准资费」栏**，而河北资费·个人有 91 条 | `getType2List` 在 `(attr=1, t1=1)` 下**没有**声明 `type2=5`。官网 `setZFLXList` 过滤后同样为空，同样不渲染这一栏 —— **官网没有，我们也不该有** |
| **全网资费·政企只有「加装包」1 栏** | `(attr=1, t1=2)` 只声明了 `type2=2`。官网同样只显示这 1 栏 |
| **河北资费·政企只有 3 栏**（无港澳台/国际、无标准资费） | `(attr=2, t1=2)` 只声明 `type2∈{1,2,3}` |

**判据方向**：官网对「过滤后为空」的处理是 `setPageState('SPECIAL_EMPTY')`
（显示空状态），本站对「该维度无数据」是隐藏该维度 —— 两者语义一致：
**这一栏不存在**，而不是「有但没采到」。

### 附带发现：403 条 `attr=3` 条目的归属

上游有 403 条条目**自身标注** `tariffAttr=3`（未启用），但它们是**通过 `attr=2` 的请求
返回**的。本站与官网的处理完全一致：

- 官网：页签只有 `rangeType` 1/2 两个；请求 `attr=2` 时返回什么就显示什么，
  **不会再按条目自身的 attr 过滤一遍**
- 本站：`sect` 按**请求组合**落盘（`g.get("tariffAttr")`），不是按条目自标注 ——
  所以这 403 条的 `sect = "本省资费"`，与官网归类一致

两个口径的数字对照（河北资费·个人）：

| 口径 | 套餐 | 加装包 | 营销活动 | 港澳台/国际 | 标准资费 | 合计 |
|---|---|---|---|---|---|---|
| 按**请求组合**（页面/官网口径） | 458 | 700 | 1050 | 3 | 91 | **2302** |
| 按**条目自标注 attr=2** | 441 | 558 | 818 | 3 | 84 | 1904 |
| 按**条目自标注 attr=3** | 17 | 142 | 232 | 0 | 7 | 398 |

1904 + 398 = 2302 ✅ —— 两种口径只是**同一批数据的两种切法**，没有丢数据。

## 四、这次顺带堵上的两个判据漏洞

核查过程中发现，**唯一能回答「栏目清单本身是否完整」的那个探针本身是坏的**：

### 4.1 移动分支从未在 CI 里执行过

`.github/workflows/tariff-daily.yml` 此前只跑 `--net unicom`，移动侧的
`[D1]/[D2]`（`getType2List` 声明的组合 vs 把 30 个组合全部暴力请求一遍）
**一次都没跑过**。已加为阻塞步骤。

### 4.2 两个分支的判据都「输入一空就恒真」

| 分支 | 空输入时的旧行为 |
|---|---|
| 移动 `[D1]` | 目录取不到 ⇒ 声明组合 0 个 ⇒ 30 次请求全返回 0（与「上游没数据」同形）⇒ 打印「采集维度穷尽 ✅」`exit 0`。**本机无密钥实测正是这个结果** |
| 联通 `[B]` | 12 城骨架全空 ⇒ 并集为空 ⇒ 打印「✅ 单城骨架已覆盖 12 城并集（一级 0 / 二级 0）—— 单城取骨架是安全的」 |
| 联通 `[C]` | 同样的口径 ⇒ 打印「✅ 只有 1/2 —— `ATTRS` 是完备的」 |

用桩函数把 `post()` 换成恒定失败实测：联通三个子项里**两个当场变绿**，
只有 `[A]` 因把空上游误当成「硬编码多出 12 城」而侥幸判红。**侥幸不是判据。**

现在每个子项都要求「**输入非空 且 无未知格**」，否则判**无法判定 = 失败**（`exit 2`）；
判红时打印上游请求统计与具体判红子项，一眼分清「真漏了」和「根本没问到」。

## 五、还没封死的一个口子

`isPublic` 取值域。官网预览态走的是 `isPublic=2`
（`'isPublic': this.isPreview ? '2' : '1'`），本站固定传 `1`。

已在探针里加 `[F]` 节探测 `isPublic ∈ {0,1,2}`，但**只报告、不判据**：
`isPublic=2` 取到的是**未公示数据**，公开站点本来就不该采，
不该因为它有数据就判红。另外区分「请求打不通」（判失败）与
「上游明确拒绝该取值」（正常结论），避免判据死于噪声。
