# AI 优化清单 —— 2026-10-01 落地与后续路线

> 本轮「AI 思维」审查的产出分两部分：**已落地**（本文档上半部分，代码已进库、
> 真实 Chrome e2e + 冒烟全绿）与**后续可选路线**（下半部分，按投入/收益排序）。

## 一、本轮已落地（5 项）

### 1. 搜索输入防抖（~150ms）
- **问题**：`#kw` 每敲一个字符就触发一轮全量 filter + sort（联通 8000+ 行，
  decorate-sort 也要 O(n) 取值），连打一串字时中间每一键都是白算。
- **做法**：只对 `#kw` 的 oninput 加 150ms 防抖；Esc 清空保持立即 apply；
  下拉 / 页签 / 快捷 chip 等离散动作不防抖（避免「点了没反应」错觉）。
- **验证**：真实 Chrome 冒烟 —— 连续两次输入后最终状态只按最后一次重算，结果正确。

### 2. 变化历史页新增「在架规模趋势」SVG 折线图
- **问题**：history.json 里每天每网的在架条数（`n`）只藏在时间线的「N 条」小字里，
  「联通在涨、移动走平」这类趋势要人脑连点十几天才看得出来。
- **做法**：纯前端从已注入页面的 `HIST` 现算画 SVG（每网一条线、四网配色沿用
  各自主题色、圆点带 `<title>` 原生提示、最多画最近 60 天）。**不新增构建期产物**，
  数据没变时输出逐字节一致，不破坏归档可逐字节比对的铁律。
- **验证**：真实 Chrome —— 4 条折线、42 个带提示的数据点、图例齐全（见
  `evidence/AI优化-在架规模趋势-20261001.png`）。

### 3. 详情展开「同价位更优选择」智能对比
- **问题**：用户盯一条 59 元 30GB 的套餐时，真正的问题是「同价位有没有更好的」；
  手动翻几千条没人会做。
- **做法**：展开详情时**按需**计算（首次展开才扫一遍全表，80 行预计算是 72 万次
  比较/渲染，绝不预计算）：同网 ±10 元档内、**流量更多且每元流量更高**的在售资费
  top3，绿徽标展示。判据复用页面既有 `perVal / num / fmtGb` 口径，不另立一套；
  无更优解时整行隐藏（诚实展示「没有」）。
- **验证**：真实 Chrome —— 有建议时正确给出（广电网第 5 条即命中 0 元 200GB 的
  更优解）；无建议时正确隐藏。

### 4. 收藏导出 / 导入（JSON）
- **问题**：收藏存 localStorage 是纯本机偏好，换设备 / 清浏览器数据就全丢。
- **做法**：「收藏导出」下载 JSON（文件名带数据基线日期，与 CSV 同一命名惯例）；
  「收藏导入」**合并**（不是覆盖）进本机收藏，只认 `网|名称` 形态的键，坏文件
  toast 提示不破坏现有收藏。
- **验证**：真实 Chrome —— 按钮与隐藏 file input 落位正确。

### 5. CI pip 缓存
- **问题**：每日巡检冷装 4 个包 + ruff 约 20~40s，纯浪费（依赖几乎不变）。
- **做法**：新增 `requirements-ci.txt` 作缓存键，`tariff-daily.yml` 与 `ci.yml` 的
  setup-python 加 `cache: pip`；改版本自动失效。

**验证汇总**：`tests/run_all.py` 5 套件全绿；`probe_sticky_layers` 通过（新 CSS
未触碰吸顶铁律）；`tariff_monitor.py --render-only` 用归档数据重渲染成功
（14480 条）；仓库自带 `page_e2e_check.js` 在真实 Chrome 里 `__allOk: true`；
新功能定向冒烟 9/9 通过。

## 二、后续可选路线（按「投入 / 收益」排序，未实施）

### A. 条目级深链（小投入，高实用）
现状深链只到「筛选条件」，分享一条具体资费要口头描述「就是那个 59 元 30GB 的」。
做法：`render()` 给行加 `#q=<报备编号或 名称hash>`，readHash 命中后滚动定位 + 高亮。
注意：报备编号 `d.r` 是最稳的键（名称可能重名）。

### B. 跨网同档对比视图（中投入，差异化价值）
现在四网只能切换着看；「同一个月费档，四网各给什么」必须人脑拼接。
做法：总览页加一个「同档横评」面板：选定月费档（如 29~39 元），四网各取
每元流量 top3 并排展示。纯前端可算，数据已齐。

### C. AI 日报摘要（中投入，需 LLM key）
五通道推送的正文是数字（新增 N / 下线 M）；「联通今天集中下线了一批校园卡」
这类**一句话结论**需要摘要能力。做法：CI 里对 diff 样本调 LLM 生成 2~3 句摘要，
追加到推送正文。走 GitHub Actions Secret，成本约 ¥0.01/天；key 缺失时自动
退回现有数字版（fail-open，不阻断巡检）。

### D. 订阅式推送（小投入）
现在推送是全量广播；「只关心宽带资费」的用户天天收全套。做法：钉钉/邮件正文
尾部加「分类订阅链接」（现有深链 `#cat=宽带` + PushPlus 自定义 topic 即可实现大半）。

### E. 数据 API（中投入，服务第三方）
页面数据全内联在 HTML 里，第三方想拿数据只能解析 11MB HTML。
做法：巡检时额外产出一份 `docs/data-latest.json`（四网行数据 + 基线元信息，
gzip 后预计 <1MB），页面不改、第三方直接 fetch。注意在 README 声明「报备公示
口径、非商用」。

### F. 前端微优化（低优先）
- 表格行 hover 展开 → 改为点击已实现；可加 `aria-expanded` 提升无障碍。
- 长表 `content-visibility:auto`（明细行超出视口的部分跳过渲染，滚动更顺）。
- `manifest.json` 可加 `screenshots` 字段，PWA 安装弹窗会更丰富。

### 明确不做（与既有结论一致）
- 河北公告抓取：nrapigate 公告端点 provinceCode=311 恒为 0 条，无数据源。
- 四网 Cookie/登录态巡检：均无需登录凭证，不适用。
- 快照保留策略：已有（KEEP_SNAPSHOTS=60），无需另做。
