## 三、明细可达性（判据④）

| 指标 | 值 |
|---|---:|
| 三级目录 id 并集 | **9121** |
| 分批拉明细（每批 ≤30 id） | 305 批，失败 **0** |
| 传入 id 合计 | 9121 |
| 返回明细条数（未去重） | **9121** |
| **差** | **0** ✅ |
| `reportNo` 去重后 | 8042 |
| 重复挂载（id 去重 − reportNo 去重） | 1079 |

> ⚠️ **别把 1079 读成「漏了 1079 条」。**
> `operateData` 的返回条数**恒等于传入 id 数**（9121 传 → 9121 回），
> 说明每个 id 都有明细。差额来自**同一资费被挂在多个栏目/板块下**
> （同一 `reportNo` 对应多个三级目录 id）。
> 判据要看 **「传入 vs 返回」**，不是 **「id 数 vs 去重数」**——后者会把重复挂载误读成丢失。
>
> 另外验过：`size` / `page` 参数**不截断也不分页**（传 60 个 id + `size=20` 仍返回 60 条，
> `page=2/3` 返回与 `page=1` 相同内容）。真正的分页参数是 `fistLimit`，
> 但那是移动那边的坑（见 `tariff_monitor.py` 注释），联通这里没有。

## 五、四网横向对照（同一套判据）

| 网 | 栏目枚举来源 | 栏目数 | 采集方式 | 覆盖结论 |
|---|---|---|---:|---|
| **移动** | `getType2List(isPublic=1)` | 18 组合（板块×栏目×个人/政企） | 逐组合 `getTariffListInfo` | ✅ 全覆盖；`attr=3` 的 5 个组合是上游**空壳**（系列=0）；`type2=7`「其他」、`attr=1/type2=5` 上游列表里就没有，`isPublic=0` 也取不到（明细=0） |
| **联通** | `indexData` | 22 组合 × 2 板块 | 12 城并集菜单 → 明细按 id 拉一遍 | ✅ 全覆盖（本文） |
| **电信** | `tariffSectionHome` 的 `lableOneList` | 5 个一级 | 真实浏览器过瑞数 WAF → `tariffSectionQuery` | ✅ **无截断**（`count == len` 逐项相等）；「国际/港澳台资费」「国内标准资费」2 栏为 0，属上游无数据 ⚠️ 待用浏览器侧再确认一次 |
| **广电** | `queryTariffCondition` 分类树 | 16 节点 / 8 个有数据 | `queryTariffAllByCond` 一次全量 | ✅ 全覆盖；`type1` 传 `GZ`/`ZQ`/`GZQY` **返回完全相同**（服务端忽略其值），`type3` 是无效参数（传了返回 0）⇒ **全量拉是唯一入口，不可能因没传 type2 而漏** |

移动侧新增两条判据：
- `getType2List` 的**必传参数是 `isPublic`**（不传返回 0 个组合），
  加 `linkScn`/`cellNum`/`type1` 都不改变全集（`type1` 只是过滤）。
- `isPublic=0` 能列出 **25 个**组合（多出 `attr=1/type2=5`、`type2=7`「其他」、政企更多组合），
  但逐个查明细**全部返回 0 条 / 系列 0** ⇒ 上游有壳无内容，**不是漏采**。
