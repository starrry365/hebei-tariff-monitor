# 河北四网资费 —— 采集完备性核查与两处归属纠错

> 2026-09-24 · 触发：用户报「我感觉你采集的还是不对，请认真完美的采集河北省的所有地市的所有栏目和业务」

---

## 0. 一句话结论

**采集的「广度」是够的**（四网 × 地市 × 栏目 × 板块四个维度逐格核过，没有整栏/整城被漏请求），
**但「归属」有两个真错** —— 它们让数据看着齐全、实则把资费放错了档：

1. **4 位地市码 `3121` 被错挂成「省直辖（定州/辛集）」，实测是「雄安新区」**
   ⇒ 雄安的 8 条资费全被记在了一个不存在的地域名下，**「雄安新区」这一档永远是空的**。
2. **上游用「把 12 个地市码全列出来」表达「全省通用」，采集侧没识别**
   ⇒ 移动 **59 条全省资费**被当成「12 城专属」，**按「仅全省通用」筛时看不到它们**。

外加两处同源隐患（文案兜底被架空、请求失败被当成空目录），一并修掉并把判据接进 CI。

---

## 1. 用户看到的现象 → 定位

用户强调「**所有地市**」「**所有栏目**」「**所有业务**」。这三样拆开看，等于在问
「**该采的维度是不是都去采了**」—— 而这件事**此前没有任何一条检查在问**。

既有检查问的都是「**已经采到的那批**对不对」（口径 / 展示 / 变更 / 对账），
两者的失效方式完全不同：

| | 失效表现 | 能不能被发现 |
|---|---|---|
| 已采数据算错 | 数字对不上 | 能，对账就报 |
| **该采的没去采 / 归错档** | 接口全 200、日志无异常，唯一症状是「少了」 | **不能 —— 少的那部分从不出现** |

本轮两个真错都属后者，所以**当时 12 项检查全绿**。

---

## 2. 真错 ①：`3121` 码名错挂（雄安 → 「省直辖（定州/辛集）」）

### 定性方法（人眼判据）

把每个 4 位码**单独出现**（`applicableArea`/`city` 恰好只含这一个码）的条目全列出来，看名字：

```
3100 邯郸      单独  40 条 · 名含「邯郸」35 条
3110 石家庄     单独  59 条 · 名含「石家庄」54 条
3120 保定      单独  34 条 · 名含「保定」34 条
3121 省直辖（定州/辛集）单独 8 条 · 名含本码名  0 条   ⚠️⚠️
3130 张家口     单独  14 条 · 名含「张家口」12 条
...
3350 秦皇岛     单独  51 条 · 名含「秦皇岛」51 条
```

`3121` 那 8 条，名字是：

```
雄安新区咪咕融合权益5次包 / 10次包 / 1次包
雄安9元返费优惠（12个月） · 雄安公交出行权益包
雄安新区咪咕咖啡体验包（12Y） · 雄安金牌服务包A（12个月）
40G通用流量包（24个月）        ← 文案里没写地名，但同批
```

**7/8 条直接写着「雄安」；其余 11 个码单独出现时名字里都各自写着自己的城市名，只有它不对。**
代号规律也自洽：雄安原属保定，`3120 保定` ⇒ `3121 雄安`。

### 后果

| | 修复前 | 修复后 |
|---|---|---|
| 「雄安新区」档 | = 不限地市那一批（**0 条专属**，看起来像「雄安没有资费」） | +14 条，含那 8 条雄安专属 |
| 「省直辖（定州/辛集）」档 | 装了雄安的资费 + 一批全省资费 | **档位已移除** |
| 上游是否真有「定州/辛集」的码 | — | **没有**（逐码单独出现的条目里一条都没有）⇒ 两点数据并入保定 / 石家庄 |

> 移动与电信**共用**这张码表，所以两网同时受影响。

## 3. 真错 ②：上游「全省通用」的第二种写法没被识别

`applicableArea` 除了**留空**（= 无地域限制），还会把 **12 个地市码全列出来**：

```
3120,3140,3170,3100,3180,3160,3350,3110,3150,3121,3190,3130,   ← 有时整串重复两遍
3120,3140,3170,3100,3180,3160,3350,3110,3150,3121,3190,3130
```

`_mk_cities()` 把 12 个码映射成 12 个市名 ⇒ 被判成「**12 城专属**」。

```
移动 applicableArea 形态：无地市码 4816 · 单码 387 · 2~9 码 33
                        ★全码（=全省写法）**59** · 10~11 码 2
```

这 59 条多是「**0预存5G金币购机合约活动**」这类**全省活动**。

**后果**：它们既不在「仅全省通用（不限地市）」档里（用户按它筛会少 59 条），
又被计进「地市专属」总数（数字虚高）。

> ⚠️ **电信那批「10~11 个码」不适用同一判据** —— 实测它们确实只限那几个市
> （农业/扶贫/宽带政策类，少的正是廊坊、唐山等），**不是全省**，不能改。
> 所以判据用「码集合 ⊇ 全部 12 码」，而不是「token 数 ≥ 12」。

## 4. 隐患 ③：文案兜底被码判定架空（与它自己的注释矛盾）

`text_cities()` 的注释写着：

> 返回数组而非单值：一条可属多市（IPTV 类在目标客户里列 4 个市；
> **「沧州华油尊享礼包」同属沧州与华北油田**）。

但 `rows_of()` 里是 `if not cty and code in CITY_TEXT` —— **只要码判定给了地市，文案就完全不看**。
于是「华北油田」这个档**永远是 0 条专属**（它的资费码是 3170 沧州 / 3160 廊坊，只有名字里带「华油」）。

**修法**：改成**互补**而非互斥 ——

* **无码** → 文案兜全量（原行为）；
* **有码** → 只让文案补 `CITY_EXTRA`（雄安新区 / 华北油田这类**没有独立地市码**的区域）。

这样既捞回了华油（13 条），又不会因为「说明里提到别的地市」而给 4 位码地市加错标签。

## 5. 隐患 ④：联通侧「请求失败」被当成「空目录」

`he_unicom_tariff.get_level3()` 原先：

```python
if r.get("code") == "0001": return []      # 空目录（正常）
if r.get("code") != "0000": return []      # ⚠️ 请求失败 —— 也返回 []
```

而联通的「不限地市 / 城市专属」判定 = **该三级目录在几个城市出现过**。
一个失败格 ⇒ 某条资费少算一个城市 ⇒ **本该「不限地市」的被改判成「N 城专属」**
⇒ 用户在其他 11 个城市按地市筛时**看不到它**。方向固定、后果静默。

**修法**：失败返回 `None`（未知）并由调用方处置 ——
立即重试一次；仍失败则**整批拒绝发布**（`RuntimeError`），
`city_scope()` 也会显式列出失败格并声明「结论不可信」。
宁可退回上一轮快照渲染（页面写明基线日期），也不发布一份把全省资费藏进某个城市档的数据。

> **本次实测：528 格全部 `0000`/`0001`，无失败格；抽 60 格连取两次逐一致** ⇒ 当前数据未被污染。

## 6. 采集维度穷尽性核查（四网逐格）

| 网 | 地市维度 | 栏目 / 板块 | 结论 |
|---|---|---|---|
| **移动** | 上游**不按地市分数据** —— 实测 `cityId` / `city` / `cityCode` / `areaCode` × 3 城**返回完全不变**（75 条 / 17 系列） | `getType2List` 声明 18 个 (attr,type1,type2)；笛卡尔积缺的 **12 个组合直接请求实测全部零数据** ⇒ 信任目录成立 | ✅ 完备 |
| **联通** | 12 城并集；上游 `cityList` **== 硬编码 12 城**；同一三级 id 用 12 个 cityId 请求**明细内容完全一致**（抽样 7 个 id） | 一级/二级骨架 **12 城签名去重 = 1 种**（单城取骨架安全，三轮稳定）；`tariffAttributes` 实测**只有 1/2**（3/4/5/空/0 全零） | ✅ 完备 |
| **电信** | 上游是 `provCode` 级（河北），条目自带 4 位码 | `lableOneList` 5 个分类**全部遍历**；2 个 0 条分类的服务端 `count` 就是 0（真空，非截断）；`lableTow` 全为空 | ✅ 完备 |
| **广电** | 上游只有 `ZZZZ`（全国）/ `HB00`（河北）两档，区域表无地市级 | 分类树 16 个叶节点 / 8 个有数据；`type1` 被服务端忽略 | ✅ 完备 |

**已知的上游限制（不是我们的漏采）**：

* 广电**没有地市维度**（传地市级编码回 `BASE102 区域编码无效`）⇒ 页面**隐藏**该维度（不是置灰）。
* 移动 `attr=3` 的 5 个组合：上游目录里有、明细接口恒返回 0 条 ⇒ **本网拿不到**已下架明细。
* 移动/电信的「华北油田」横跨沧州与廊坊，上游**没有**它的独立码，只能靠文案。

## 9. 遗留 / 需要确认

1. **用户看到的具体现象尚未对齐。** 本轮是从「维度穷尽性」出发自查出的两个真错；
   如果用户看到的「不对」是**另一个**具体现象（某个市 / 某个栏目 / 与上游 App 对不上），
   请指明，可据此再查 —— 现有探针已能直接回答「这个市独有目录是什么」
   （`probes/probe_city_only.py --city <名>`）。
2. 移动 `attr=3` 的已下架明细**本网取不到**（上游恒 0 条），非本次可解。
3. 「不限地市」那批在任意地市档下都会计入 ⇒ 地市筛选对以全省为主的网收窄作用有限。
   若需要「**只看这个市独有**」，需再加一个档位（当前刻意不加）。
4. 浏览器类检查（walk / e2e / conformance）**仍只在本地跑**，未进 CI。
